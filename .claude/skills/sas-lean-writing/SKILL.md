# sas-lean-writing

산문(주석·문서·메모리·채팅 응답 등)에서 비표준 기호, 근거 없는 인용, 군더더기 이력,
뭉텅이 텍스트를 없애고 구조화된 글로 다듬는다.

## 대상과 경계

- 대상: 주석, 문서·설명글, 메모리, 채팅 응답 등 산문 전반. 동작을 정의하는 기능성
  작성 자체가 목적은 아니지만, 스킬·커맨드·에이전트 같은 기능성 문서의 산문 부분에도
  청결함과 자연스러운 맥락 유지를 위해 보조적으로 쓰일 수 있다.
- 기능성 문서에서는 표현만 고친다. frontmatter, 명령, 조건, 경로, 출력 형식처럼 동작을
  정하는 부분은 바꾸지 않는다.
- 대상 아님: PRD·plan처럼 원래 참조·의사결정 이력을 담는 게 목적인 문서(「부가 정보·
  이력 배제」 기준과 충돌한다).

## 핵심 기준

| 기준                  | 내용                                                                                                                                                                                                                                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 자기완결성            | 본문만으로 이해되어야 한다. 저장소 안의 일시적 문서(합의 경위, 이전 논의 등)를 근거처럼 인용하지 않는다. 인용 가능 범위는 글의 성격에 따라 다르며, 명시적 요청이 있으면 같은 체계 안의 문서끼리 서로 참조할 수 있다(「자기완결성: 인용 가능 범위」 참조).                                                       |
| 목적에 맞는 표준 표기 | 문서의 확장자·목적에 맞는 표준 표기만 쓴다. 다른 장르의 관례를 가져오지 않는다. 예: 일반 문서(README 등)에 법률·학술 문서의 절 기호 "§"를 쓰지 않는다, 한글 모음 필러 "ㅡ"를 대시 대용으로 쓰지 않는다, 하이픈("-")을 일반 구두점 대용으로 남용하지 않는다(목록 기호·복합어·범위 표기 같은 표준 용법에만 쓴다). |
| Lean(군더더기 없음)   | 글자 수를 줄이는 게 목적이 아니다. 불필요한 수식어·중복 표현·에두른 말 같은 군더더기만 걷어내고, 필요한 내용은 그대로 유지한다.                                                                                                                                                                                 |
| 부가 정보·이력 배제   | 본문 내용과 무관한 히스토리("예전엔 이랬는데 지금은"), 합의 경위, changelog성 서술을 넣지 않는다.                                                                                                                                                                                                               |
| 구조적 글쓰기         | 문단을 내용 단위로 분리하고, 필요하면 표·리스트 등으로 정보를 구조화한다. 하나의 텍스트 뭉텅이로 늘어지지 않게 한다.                                                                                                                                                                                            |
| 독자 고려             | 읽는 대상은 LLM이 아니라 사용자(인간)라는 전제로, 필요한 배경과 맥락을 생략하지 않고 쉽고 상세하게 쓴다.                                                                                                                                                                                                        |
| 자연스러운 흐름       | 초안이든 기존 글 수정이든, 결과는 처음부터 그렇게 쓴 것처럼 자연스럽게 읽혀야 한다. 항목을 기계적으로 나열하지 않는다. 수정 시 바뀐 부분을 문장 끝에 덧붙이지 말고, 문맥이 이어지도록 필요한 만큼 앞뒤 문장을 함께 고쳐 써서 이어붙인 티가 나지 않게 한다.                                                      |

### 자기완결성: 인용 가능 범위

| 구분                         | 설명                                                                                                                                                                               | 예                                                                                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 대상을 설명하는 글           | 설명에 필요한 것을 함께 인용할 수 있다.                                                                                                                                            | 주석이 가리키는 실제 코드, README가 설명하는 실제 프로젝트 구조, docs/memory가 설명하는 실제 코드·설정, 공식 문서·기사 등 공신력 있는 외부 출처 |
| 명시적 요청이 있는 문서 체계 | 같은 체계 안의 다른 문서를 링크로 참조할 수 있다. 겹치는 내용은 한 문서에만 두고 나머지는 링크로 가리킨다. 요청은 사용자의 지시이거나, 이 스킬을 부르는 지침이 정한 문서 형식이다. | 옵시디언 형식의 docs/memory 가 위키링크로 서로 연결되는 경우                                                                                    |
| 그 외                        | 명확한 의존 관계가 없는 한 공신력 있는 외부 출처만 인용할 수 있다.                                                                                                                 | 동작을 정의하는 글이 근거 없이 특정 환경·하네스를 언급하지 않음                                                                                 |
