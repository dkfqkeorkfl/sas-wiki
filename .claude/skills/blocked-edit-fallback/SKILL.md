# blocked-edit-fallback

permissions.deny 규칙이나 프로젝트의 보호 훅에 쓰기가 막힌 파일을 정말 수정해야 할
때 따르는 절차다. 목표는 하나다: 차단을 우회하지 않고, 변경 결정 자체를 사용자에게
넘긴다.

read는 열려 있고 write(또는 bash)만 막힌 경우를 전제한다. Read 도구까지 막혀 있으면
이 절차를 쓰지 않는다. 원본을 알아낼 안전한 방법이 없고 사용자에게 내용을 묻는
것도 보호 취지를 해치므로, 시도를 멈추고 상황만 설명한다. 자격증명·비밀 파일도 이 절차의
대상이 아니다.

## 하지 않는 것

- 차단 설정(예: `.claude/settings.json`의 permissions.deny, 보호 훅의 설정 파일)을
  고쳐서 차단을 풀고 다시 시도하지 않는다. 그 설정이 걸려 있는 데는 이유가 있다고
  가정한다.
- 심링크나 훅이 못 보는 다른 도구 경로로 차단을 피해 가지 않는다.
- Bash나 스크래치패드를 이용해 차단을 우회하는 스크립트나 명령을 작성하거나
  실행하지 않는다.
- Codex나 MCP 같은 외부 도구·에이전트에 위임해서 차단을 우회하지 않는다.
- 사용자 대신 적용 명령(`cp`/`mv` 등)을 실행하지 않는다. 최종 판단은 사용자 몫이다.

## 절차

1. **원본을 읽는다.** Read 도구로 현재 내용을 확인한다.
2. **변경안을 세션 스크래치패드에, 원본 파일명과 무관한 임시 이름으로 작성한다.**
   차단 규칙 중 `~/`·`/`·`./` 접두사가 붙은 경로 한정 규칙은 그 경로 하나만 가리키므로
   스크래치패드로 옮기면 걸리지 않지만, 접두사 없는 규칙(`*.pem`, `id_rsa*` 같은 파일명
   패턴)은 어느 경로에 있든 파일명만으로 매칭된다. 원본 파일명을 스크래치패드에 그대로
   재사용하면 그 규칙이 새 위치에서도 다시 걸릴 수 있으므로, 원본 이름·확장자를 재사용하지
   않는 임시 이름(`draft-1`, `draft-2`...)으로 쓴다. 디렉터리 구조는 식별하기 쉽게 그대로
   살려도 된다(차단 규칙과는 무관하다).
3. **무엇이 왜 바뀌는지 사용자에게 설명한다.** 전체 파일을 다시 나열하지 않고, 바뀐
   지점과 이유만 명확히 전달한다(필요하면 `diff`를 보여줘도 된다).
4. **적용 명령을 `!` 접두사로 제시한다.** 사용자가 이 대화창에 그대로 붙여넣어
   실행할 수 있게 한다:
   ```
   !mv -- '<스크래치패드 경로>' '<원본 경로>'
   ```
   스크래치패드 파일 내용을 사용자가 직접 복사해 붙여넣게 하지 않는다. `mv`나 `cp`가
   파일을 그대로 옮기므로 명령 한 줄이면 충분하다. 임시 이름으로 썼더라도 이 명령이
   목적지 경로의 파일명(원본 이름)으로 정확히 옮겨 놓으므로 결과 파일명은 그대로다.
   경로는 작은따옴표로 감싸고 `--`를 붙인다. 작은따옴표 안에서는 아무것도 해석되지
   않아 공백이나 특수문자가 있는 경로에서도 그대로 동작한다. 기본은 `mv`다. 적용과
   동시에 스크래치패드 사본이 사라져 따로 정리할 필요가 없기 때문이다. 원본이 실행
   파일이면 `cp`를 쓴다. `mv`는 사본의 모드를 그대로 가져가지만, 기존 파일 위에
   `cp` 하면 원본의 모드가 유지된다.
5. **결과를 검증한다.** 사용자가 명령을 실행한 뒤 필요하면 테스트 실행 등으로
   확인한다. `cp`를 썼다면 검증 후 스크래치패드 사본을 삭제한다.

## 여러 파일을 한 번에 고쳐야 할 때

적용 명령이 짧으면 `cp`/`mv`를 `&&`로 이어 붙여 한 줄짜리 `!` 명령으로 제시한다:

```
!mv -- '<스크래치패드 경로 1>' '<원본 경로 1>' && mv -- '<스크래치패드 경로 2>' '<원본 경로 2>'
```

명령이 많아 한 줄로 확인하기 어려우면 세션 스크래치패드에 적용용 Bash 스크립트로
묶을 수 있다. 이때는 다음 순서로 안내한다.

1. **동작과 적용 대상을 설명한다.** 파일 변경 내용과 별도로, 각 사본의 출발지·목적지,
   덮어쓰기 범위와 부수 동작을 설명한다.
2. **실행할 코드를 보여주고 사용자 확인을 받는다.** 짧으면 전체 코드를 보여준다.
   길면 주요 코드와 전체 스크립트를 확인할 경로를 함께 제공한다. 설명만으로 실제
   실행할 전체 코드를 확인할 수 없게 하지 않는다.
3. **확인 후 실행 명령을 제시한다.** 사용자가 직접 실행하도록
   `!bash -- '<스크립트 경로>'`를 안내한다. 확인받은 뒤 스크립트를 변경하면 변경 내용을
   다시 보여주고 확인받는다.

적용 스크립트는 사용자가 검토·실행할 명령을 묶는 용도다. 차단을 우회하는 수단으로
쓰거나 사용자 대신 실행하지 않는다. 경로 인용과 실행 파일의 모드 보존은 위의 적용
명령 기준을 따른다.
