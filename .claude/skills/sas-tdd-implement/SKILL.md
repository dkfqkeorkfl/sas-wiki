# sas-tdd-implement

단계별 위임과 결과 처리를 관리한다. 각 단계의 수행 방법은 위임받는 쪽이 판단하며, 이 스킬은 담당 선택·실행 순서·맥락 전달·문제 처리를 맡는다.

## 입력과 실행 방식

구현 대상 스펙·범위·요구 조건·컨벤션과 필요한 이전 단계 산출물을 받는다.

| 입력                                | 실행 방식                                                                          |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| 단계 플래그 없음                    | 같은 작업의 RED→GREEN→REFACTOR를 순서대로 수행                                     |
| `--red` / `--green` / `--refactor`  | 지정한 단계만 수행                                                                 |
| 서로 독립된 작업의 여러 단계 플래그 | 각 작업과 단계의 대응을 확인하고 병렬 수행                                         |
| 단계 플래그 + `--continue`          | 이미 위임한 해당 작업·단계에 추가 지시를 전달해 이어가기(예: `--green --continue`) |

## 위임 경로와 모델·effort 기준

| 단계         | 1순위                            | 2순위                        | 전달 가이드                                       | 비고                                                            |
| ------------ | -------------------------------- | ---------------------------- | ------------------------------------------------- | --------------------------------------------------------------- |
| RED          | `sas-tdd-guide`                  | 없음                         | 해당 에이전트의 정의                              | RED 테스트와 GREEN 인계 사항                                    |
| GREEN: 단순  | 하이쿠 (즉석 범용 서브에이전트)  | 없음                         | [green-guide.md](references/green-guide.md)       | 기계적·지시 명확·단순 반복. 실패하면 그 밖의 GREEN으로 재분류   |
| GREEN: 그 밖 | 솔, high (`/cc-suite:implement`) | `tdd-guide`                  | [green-guide.md](references/green-guide.md)       | 단순 코딩인지 애매한 경우도 포함                                |
| REFACTOR     | 솔 (`/cc-suite:implement`)       | 전문 에이전트 또는 범용 소넷 | [refactor-guide.md](references/refactor-guide.md) | 수정 모드. 전문 에이전트는 `sas-refactoring-master` 등에서 선택 |

정의된 에이전트의 모델 선언은 유지한다. 명시하지 않은 effort와 실패 시 전환은 아래 「위임 실행 규칙」을 따른다.

## 위임 실행 규칙

### 모델·effort와 위임 한도

- **effort**: 명시한 effort(사용자 지정, 표·스킬에 적힌 값)가 없으면 기본적으로 high를 쓰되 복잡도에 따라 xhigh까지 사용할 수 있다.
- **위임 수**: 위임은 건수로 센다(서브에이전트 호출 하나, Codex 호출 하나가 한 건). 호출자는 자기가 직접 띄운 위임만 자기 실행 한 번 동안 합산하며, 비슷한 일은 정확도를 해치지 않는 범위에서 묶어 맡긴다. 한도를 넘기면 위임 전에 확인을 받는다. `inherit`인 정의 에이전트 호출과 재시도·이어가기·다음 순위 전환은 세지 않는다.

  | 모델                             | 한도                                                   |
  | -------------------------------- | ------------------------------------------------------ |
  | 루나·하이쿠                      | 5건                                                    |
  | 소넷·솔                          | 3건                                                    |
  | 프론티어(페이블·오푸스·아스트라) | 동시 1건                                               |
  | 전체                             | 5건 (예: 프론티어 1건 + 소넷·솔 2건 + 루나·하이쿠 2건) |

### 호출 제약과 이어가기

- **호출 제약**: Codex MCP는 사용하지 않는다.
- **이어가기**: 맥락 유지가 필요하거나 재시도할 때는 처음 사용한 호출 경로로 이어간다(cc-suite는 `/cc-suite:continue`, sas-codex-chat은 `--resume`).
- **이어가기 effort**: Codex 이어가기 호출 시 기존 작업의 effort를 `--effort`에 명시적으로 다시 전달한다. 사용자 지시나 해당 단계의 기준으로 변경하면 변경한 값을 전달한다. 기존 값이 불명확하면 이전 호출 정보나 해당 작업의 effort 기준으로 확인하며, 러너 기본값에 맡기지 않는다.
- **cc-suite 실행 제한**: 신규 실행과 `/cc-suite:continue` 모두 러너에 `--timeout-ms 7200000`(2시간)을 명시한다.
- **cc-suite preflight**: `/cc-suite:*` 호출은 preflight 를 자동으로 돌린다. 이때 `$'\r': command not found` 같은 셸 오류가 나오면 cc-suite 상류 저장소가 CRLF 로 체크아웃된 것이다. `sas-setup-project` 가 최초 세팅 때 LF 로 변환해 두지만 플러그인 업데이트로 다시 롤백될 수 있으며, 같은 변환을 다시 돌리면 해결된다.

### 실패·재시도·후순위 전환

- **실패와 멈춤**: 실패와 멈춤(stalled)은 구분하며 멈춤을 실패로 가정하지 않는다. 호출자에 의해 hang으로 판단 시 오류로 판단한다.
  - 실패는 최대 1회 재시도할 수 있으며 기계적으로 1회를 반드시 재시도 하지 않는다. 명백한 오류로 사용할 수 없을 때에는 후순위가 사용된다(cc-suite의 내장 폴백은 쓰지 않는다). 후순위까지 안 되면 호출한 쪽에 보고한다.

## 진행 절차

### 1. 작업 준비

작업별 스펙·범위·실행 단계와 이전 산출물을 확인한다. 같은 작업의 단계는 앞 단계의 결과를 사용하며, 병렬 작업은 서로 입출력·상태에 영향이 없다는 호출 측의 전제를 확인한다.

RED를 수행할 때는 GREEN에 필요한 하네스·패키지가 예상되면 `sas-tdd-guide` 호출 전에 준비한다. GREEN 담당은 새 패키지·도구를 설치하지 않는다. 단독 단계나 이어가기도 필요한 기존 산출물과 맥락을 전달한다.

### 2. 위임 실행

「위임 경로와 모델·effort 기준」에 따라 담당·모델·effort를 정하고, 스펙·범위·이전 산출물과 해당 가이드를 전달한다. 가이드의 전달 방법은 「단계별 가이드」를 따른다.

표에 없는 sandbox 등은 정해진 지침·설정을 적용한다. 설정이 없으면 preflight 결과를 바탕으로 `AskUserQuestion`으로 확인한다. 단계 완료 후 다음 행동은 이 스킬의 절차에 따라 결정한다.

- **순차·병렬**: 같은 작업의 단계는 순서대로 진행한다. 독립된 작업은 작업별 서브에이전트에 해당 단계와 위임 기준을 맡겨 병렬로 진행하고, 각 결과를 회수한다.
- **cc-suite 호출 경합**: `/cc-suite:*`는 한 번에 하나만 호출한다. 병렬 작업에서 cc-suite 경로가 여러 개 필요하면 오케스트레이터가 위임 전에 호출 경로를 배정한다. 한 작업만 1순위를 사용하고 나머지는 표의 2순위를 사용한다. GREEN과 REFACTOR가 경합하면 GREEN을 우선한다. RED와 단순 GREEN은 이 경합과 무관하다.
- **이어가기·인계**: Codex의 대화 번호(`threadId`)·적용한 effort와 에이전트의 작업 맥락을 작업·단계별로 유지한다. 추가 지시나 결정한 조치는 Codex에는 `/cc-suite:continue`로, 에이전트에는 같은 작업에 포함해 다시 전달한다. 이어가기 정보가 없거나 작업과 대응되지 않으면 임의의 세션으로 연결하지 않고 필요한 정보를 확인한다. 담당 전환 시 기존 변경을 보존하고, 다음 담당에게 진행 상황을 전달해 이어갈지 새로 시작할지 판단하게 한다.

### 3. 결과 확인과 처리

요청한 단계의 산출물과 지시사항·작업 범위의 이탈 여부를 확인한다. 위임받은 쪽은 범위 확장, 지시와 다른 수행, 대안 판단, 진행 불가(BLOCKED) 등의 특이사항을 우회하지 않고 멈춰 보고하도록 한다.

| 상황                                 | 오케스트레이터의 처리                                                        |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| 하네스·패키지 등 환경 문제로 BLOCKED | 설치·설정을 직접 정비하고 기존 작업을 재개                                   |
| 사양·범위·대안 등 판단 필요          | 가볍거나 명확하면 자율적으로 결정. 파괴적이거나 중대하면 사용자 확인 후 결정 |
| 담당 변경 또는 추가 지시 필요        | 기존 변경·결정·산출물을 같은 작업의 다음 호출에 전달                         |

필요한 조치를 전달한 뒤 같은 작업을 이어가게 하고 결과를 다시 확인한다. 요청한 단계가 모두 끝나면 산출물과 처리한 특이사항을 호출한 쪽에 보고한다.

## 단계별 가이드

GREEN과 REFACTOR 가이드는 담당이 Codex인지 에이전트인지와 무관하게 동일한 내용을 전달한다. 경로는 이 스킬 폴더 기준이다. Codex와 에이전트 호출 모두 파일 내용을 실행 프롬프트에 포함한다.

- **GREEN**: 최소 구현의 범위와 제한, 관련 범위 테스트 검증을 정의한다.
- **REFACTOR**: 동작 보존, 구조 정리의 판단 기준, 관련 범위 테스트 검증, 제안·잔여 부채의 보고 형식을 정의한다.

두 가이드에는 특이사항 보고와 코드·주석의 자기완결성 규약도 포함한다. RED는 `sas-tdd-guide`의 정의를 따른다.

## 산출물과 완료 기준

요청한 단계별로 RED 테스트·GREEN 인계 사항, GREEN 프로덕션 코드, REFACTOR 정리된 코드·보고를 반환한다. 담당·실행 경로와 처리한 특이사항, 수행한 관련 검증과 결과를 함께 보고한다.

요청한 단계(플래그 없으면 세 단계 모두)의 수행이 끝나고, 요청 범위의 수행을 막는 문제가 해소돼야 완료한다. 진행할 수 없으면 완료로 처리하지 않고 원인과 필요한 조치를 BLOCKED로 보고한다. 범위 밖 제안과 남겨 둔 부채는 이유를 보고하며, 이번 단계의 필수 수행 항목으로 확대하지 않는다.
