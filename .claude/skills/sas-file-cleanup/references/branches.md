# 머지된 브랜치 정리

기본 브랜치에 이미 합쳐진 브랜치를 찾아, 사용자가 한 줄로 지울 수 있는 명령을 제시한다.
로컬 브랜치가 대상이고, 머지됐는데 원격에 아직 남아 있는 브랜치는 원격 삭제 명령도 함께
제시한다. 삭제 자체는 사용자가 하고, 제시하는 것은 안전한 삭제뿐이다. 브랜치 삭제는 되돌리기
번거롭고 판정이 틀릴 수 있어서, 강제 삭제는 제시하지 않고 마지막 확인을 사람이 하게 한다.

## 제외

- 현재 체크아웃된 브랜치와 기본 브랜치.
- 다른 worktree에 체크아웃된 브랜치(`git worktree list`).
- 버전 브랜치. 태그 대신 브랜치로 버전을 표시하는 저장소가 있다. 이름이 버전·릴리스 형식
  (`release/1.2`, `v1.2.0`, `1.x`, `stable` 등)이고, 기본 브랜치의 어느 지점에 머물러 있거나
  (추가 커밋이 없어 조상 관계로는 머지된 것처럼 보인다) 머지되지 않은 채 유지되는 브랜치는
  버전 표시용으로 보고 제외한다. 저장소가 그렇게 버전을 관리하는지는 태그 유무, CHANGELOG,
  기존 브랜치 이름의 관례로 판단하고, 확신이 없으면 표에 "보류"로 적고 명령을 적지 않는다.

## 머지 판정

기본 브랜치는 `git symbolic-ref refs/remotes/origin/HEAD`로 알아내고, 없으면 `main`/`master`
중 존재하는 것을 쓴다. 근거는 아래 넷이며, 표에 어느 근거인지 적는다. 원격 브랜치는
`git fetch --prune` 뒤 `origin/<이름>` 참조에 같은 판정을 적용한다.

| 근거          | 방법                                                                                                                                | 잡아내는 것                          | 한계                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------- |
| 조상 관계     | `git branch --merged <기본>` (원격은 `git branch -r --merged <기본>`)                                                               | merge commit, fast-forward           | squash·rebase 머지는 못 잡음                |
| 스쿼시 머지   | 브랜치의 트리를 merge-base 위에 임시 커밋으로 얹고 `git cherry <기본> <임시 커밋>`이 `-`를 내면 같은 변경이 기본 브랜치에 이미 있다 | squash 머지(여러 커밋이어도)         | 머지 뒤 브랜치에 새 커밋이 붙었으면 못 잡음 |
| upstream 소멸 | `git fetch --prune` 뒤 `git for-each-ref --format='%(refname:short) %(upstream:track)' refs/heads`의 `[gone]`                       | PR 머지 후 원격 브랜치가 삭제된 경우 | 머지 없이 원격만 지운 경우도 같게 보임      |
| PR 상태       | GitHub MCP로 해당 head 브랜치의 PR이 merged인지 조회. MCP가 없으면 `gh pr list --state merged --head <브랜치>`                      | squash·rebase 머지                   | 원격이 GitHub가 아니면 불가                 |

스쿼시 판정 명령:

```bash
base=$(git merge-base <기본> <브랜치>)
tmp=$(git commit-tree "$(git rev-parse <브랜치>^{tree})" -p "$base" -m squash-check)
git cherry <기본> "$tmp"     # 출력 첫 글자가 '-' 이면 스쿼시 머지됨
```

이때 만들어지는 임시 커밋은 어떤 참조도 가리키지 않아 `git gc`가 알아서 치운다. 따로 지우려고
`git prune` 같은 명령을 돌리지 않는다.

`git fetch --prune`이 실패하면(인증 등) upstream 소멸 근거와 원격 판정은 쓰지 않고, 표에 그
사실을 적는다.

## 어떤 명령을 제시하나

| 근거                                       | 제시                                 | 이유                                                                                                                                 |
| ------------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 조상 관계                                  | `git branch -d`                      | 안전장치는 확인한 조상 관계 근거다. upstream이 설정된 브랜치는 `-d`가 upstream 기준으로 판단해 지울 수 있으므로 `-d`는 보조일 뿐이다 |
| 조상 관계이고 원격에 아직 남아 있음        | `git push origin --delete` (별도 줄) | PR이 원격을 지우지 않은 경우다. `[gone]`이면 이미 없으므로 제시하지 않는다                                                           |
| 스쿼시 머지 또는 PR merged, 조상 관계 없음 | 제시하지 않음                        | `-d`는 거부하고 `-D`는 강제 삭제라 제시하지 않는다. 근거를 표에 적고 "강제 삭제 필요"로 남긴다                                       |
| upstream 소멸뿐, 다른 근거 없음            | 제시하지 않음                        | 머지 없이 지운 원격일 수 있다. "판정 불가"로 남기고 명령을 적지 않는다                                                               |

`git branch -D`, `--force`, `+refspec` 같은 강제 삭제는 어떤 근거에서도 제시하지 않는다. 원격
삭제는 같은 원격을 쓰는 모든 사람에게 보이는 변경이라, 근거를 표에 적고 로컬 명령과 줄을
나눈다. 판정 불가·보류·강제 필요 항목에는 참고용이라도 삭제 명령을 적지 않는다. 명령이 적혀
있으면 결국 실행된다.

## 제시 형식

```
!git branch -d feat-a feat-b
!git push origin --delete feat-a    # 원격에 남아 있음
```

`git branch -d`는 현재 체크아웃한 브랜치와 upstream을 기준으로 머지 여부를 판단하므로, 기본
브랜치를 체크아웃한 상태에서 실행하라고 함께 안내한다.
