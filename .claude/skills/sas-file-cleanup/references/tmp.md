# 임시 파일 정리

`/tmp`는 LLM 세션·IDE·설치 도구가 흔적을 남기고 치우지 않는 곳이다. 살아 있는 것만 남기고
잔해를 지워 용량을 관리한다.

## 살아 있음의 근거

이름을 보고 판단하지 않는다. 아래 근거가 하나라도 있으면 보존한다.

| 근거                       | 확인 방법                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 살아 있는 유닉스 소켓      | `/proc/net/unix`(또는 `ss -lx`)에 경로가 있는 소켓 파일과 그 상위 디렉터리. IDE·MCP·git 인증 연결이 여기에 걸린다.                   |
| 현재 세션                  | 이 세션의 스크래치패드(`/tmp/claude-<uid>/<프로젝트 슬러그>/<세션 ID>/`). 다른 세션 ID의 것은 실행 중 프로세스가 쓰지 않으면 잔해다. |
| 실행 중 프로세스가 쓰는 것 | 프로세스가 열어 둔 파일(`/proc/<pid>/fd`가 가리키는 경로)이나 작업 디렉터리.                                                         |
| 재생성 가능한 캐시         | 컴파일·패키지 캐시는 지워도 되지만 다음 실행이 느려질 뿐이므로 기본 보존. 용량이 클 때만 후보로 올린다.                              |

근거가 없는 것은 삭제 후보다: 빈 해시 디렉터리, 죽은 소켓 파일, 이전 컨테이너 세션의 IPC
잔해, 설치 zip, 프롬프트·로그 텍스트, 지난 세션 스크래치패드.

## 보고 형식

항목을 하나씩 나열하지 않고 성격별로 묶어 용량과 개수를 보여준다. 사용자가 고르는 단위가
묶음이기 때문이다.

```markdown
③ tmp: 총 405MB

| 묶음                   | 개수 | 용량  | 판정 | 근거                          |
| ---------------------- | ---- | ----- | ---- | ----------------------------- |
| 지난 세션 스크래치패드 | 12   | 300MB | 삭제 | 세션 종료, 쓰는 프로세스 없음 |
| 패키지 캐시            | 1    | 100MB | 보존 | 재생성 가능, 기본 보존        |
| 설치 잔해(zip)         | 3    | 5MB   | 삭제 | 설치 끝남                     |
| IPC 소켓·디렉터리      | 8    | 0MB   | 보존 | /proc/net/unix 에 살아 있음   |
```

## 절차

```text
1. 측정: du -sh /tmp 와 항목별 크기. /tmp/* 글롭은 보호 경로를 가리키는 심링크까지 확장해
   훅에 막힐 수 있으니 ls -A /tmp 로 목록을 뽑아 항목별로 다룬다.
2. 근거 수집: /proc/net/unix 소켓 목록, 현재 세션 ID, 열린 파일.
3. 묶음별 표로 보고한다(위 형식).
4. 컨펌 뒤 삭제. 권한 오류(다른 사용자 소유)나 권한 규칙·보호 훅에 거부된 항목은 건너뛰고,
   보고의 "남긴 것"에 이유와 함께 적는다. 사용자에게 삭제 명령을 넘기지 않는다.
5. 용량 전후를 보고한다.
```

세션 transcript(`~/.claude/projects/.../*.jsonl`)는 이 영역이 아니다. 지우면 지난 세션을
이어갈 수 없다.
