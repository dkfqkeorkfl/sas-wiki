# sas-file-cleanup

불필요하거나 더 이상 쓰지 않는 데이터를 정리한다. 모든 phase가 끝난 PRD 폴더, 기본 브랜치에
머지된 브랜치(원격에 남은 것 포함), `/tmp`의 잔해가 대상이고, 메모리 두 저장소의 관리는 매번
함께 한다. 세 영역을 한 번에 스캔해 보고하고, 사용자가 고른 영역만 실행한다. 삭제는 되돌릴 수
없으므로 무엇을 왜 지우는지 먼저 보여주고 승인받은 뒤에만 손댄다.

## 영역

| 영역           | 대상                                         | 처리                                                                                | 실행 주체                     | 상세                        |
| -------------- | -------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------- | --------------------------- |
| ① PRD 아카이브 | 모든 phase가 끝난 `docs/prds/{feature}/`     | 남길 결정을 메모리에 편입한 뒤 폴더를 `_archive/`로 이동                            | 스킬(편입은 에이전트)         | `references/prd-archive.md` |
| ② 브랜치       | 기본 브랜치에 머지된 브랜치(로컬, 남은 원격) | 삭제 명령 제시. 로컬은 `git branch -d`, 원격은 `git push origin --delete`           | 사용자                        | `references/branches.md`    |
| ③ tmp          | `/tmp` 전체(Claude Code 스크래치패드 포함)   | 살아 있는 것만 남기고 잔해 삭제                                                     | 스킬                          | `references/tmp.md`         |
| 메모리 (항상)  | 자동 메모리, `docs/memory`                   | `sas-memory-manager` 에이전트가 점검·관리. ①을 고르면 PRD 결정 편입도 같은 호출에서 | `sas-memory-manager` 에이전트 | `references/memory.md`      |

메모리 관리는 선택지가 아니라 기본 실행이다. 낡거나 겹치는 메모리도 치워야 할 데이터이기
때문이다. 사용자가 명시적으로 빼라고 할 때만 건너뛴다. 영역별 판단 기준과 절차는 상세 파일에
있다. 다룰 영역의 파일만 읽는다.

## 호출

`/sas-file-cleanup`. 기본은 세 영역 모두 스캔한다. 사용자가 말로 영역을 지정하면 그 영역만
다룬다.

| 요청 예                                   | 다루는 영역    |
| ----------------------------------------- | -------------- |
| "정리 좀 해줘", "청소해줘"                | 세 영역 전부   |
| "끝난 PRD 아카이브해줘"                   | ① PRD 아카이브 |
| "머지된 브랜치 지워줘"                    | ② 브랜치       |
| "/tmp 용량 줄여줘", "스크래치패드 치워줘" | ③ tmp          |

이 스킬은 사용자의 명시적 요청으로만 시작한다. 다른 작업의 끝에 자동으로 이어 붙지 않는다.

## 절차

```text
1. 스캔   세 영역 후보와 근거를 읽기만으로 모은다. 아무것도 바꾸지 않는다. 브랜치 판정용
          git fetch --prune 만 예외로, 원격 추적 정보를 갱신한다.
2. 보고   영역별로 무엇이 얼마나 있는지, 사용자가 고를 수 있게 쉽고 상세히 정리한다.
          ① 완료 PRD 목록과 phase 근거
          ② 머지된 브랜치 목록과 근거, 원격에 아직 남아 있는지
          ③ /tmp 를 성격별로 묶은 용량(예: 지난 세션 스크래치패드 12개 300MB, 패키지 캐시 100MB,
             설치 잔해 5MB)과 보존할 것
          후보가 없는 영역은 "해당 없음"으로 적는다. 메모리 관리는 컨펌 뒤 항상 실행한다고 한
          줄로 알린다. 메모리 저장소를 열어 보는 것은 무방하지만(에이전트가 한 일을 확인할 때도
          같다), 무엇을 남기고 지울지 판정하고 관리하는 것은 에이전트의 몫이다.
3. 컨펌   AskUserQuestion 다중 선택으로 ①②③ 중 진행할 영역을 고르게 한다. 후보 없는 영역은
          선택지에서 뺀다. 특정 항목 제외 요청("feat-c는 남겨")은 반영한다.
4. 실행   선택된 영역과 메모리 관리.
          a. sas-memory-manager 에이전트를 Agent 도구로 호출한다. 요청은 두 저장소의 점검·관리이고,
             ①을 골랐으면 완료 PRD의 결정 편입을 더한다. 에이전트는 판정 결과를 돌려주고
             멈추므로, 이 스킬이 그 결과를 사용자에게 확인받은 뒤 승인 항목을 같은 에이전트에
             이어 보내 적용까지 하게 한다. ③ tmp 삭제는 이와 동시에 진행한다. 둘은 서로 의존하지
             않는다.
          b. ① 에이전트가 끝나면 PRD 폴더를 git mv 로 _archive/ 에 옮긴다.
          c. ② 브랜치 삭제 명령(!git branch -d …, 원격에 남은 것은 !git push origin --delete …)은
             5의 보고 마지막 줄에 둔다. 사용자가 실행하는 일이라 맨 끝이다.
5. 보고   결과 표, 용량 전후, git 상태(커밋 안 함), 마지막 줄에 브랜치 삭제 명령. 이 보고로
          스킬을 끝낸다.
```

## 공통 규칙

- **보존 판단은 근거로 한다.** 이름 목록을 외워서 보존하지 않는다. 살아 있는 소켓, 실행
  중인 프로세스, 현재 세션처럼 "아직 쓰인다"는 근거가 있으면 보존하고, 근거를 못 찾으면 삭제
  후보에 넣되 근거 부족을 표에 적는다.
- **브랜치 삭제는 사용자가 한다.** 되돌리기 어려운 결정을 사람이 마지막에 확인하게 하기
  위해서다. 사용자가 이 대화창에 그대로 붙여넣어 실행할 수 있게 `!` 접두사 한 줄 명령으로
  제시하고, 여러 브랜치는 한 명령에 인자로 이어 붙인다. 로컬 삭제와 원격 삭제는 줄을 나눈다.
  안전한 삭제만 제시한다. `git branch -D`나 `--force` 같은 강제 삭제는 제시하지 않고, 강제가
  필요한 브랜치는 근거와 함께 표에 남긴다. 사용자에게 실행을 넘기는 명령은 브랜치 삭제뿐이다.
  다른 영역에서 권한 규칙이나 보호 훅이 삭제를 거부한 항목은 건너뛰고 보고의 "남긴 것"에
  이유와 함께 적는다.
  ```
  !git branch -d feat-a feat-b
  !git push origin --delete feat-a
  ```
- **커밋하지 않는다.** 저장소 안 변경(`docs/prds`, `docs/memory`)은 작업 트리에 남기고 git
  상태를 보고한다. 커밋은 사용자가 따로 요청할 때 한다.
- **자기 잔해를 남기지 않는다.** 이 스킬이 만드는 임시 파일은 세션 스크래치패드에만 쓰고
  끝나면 지운다.

## 보고

```markdown
## 정리 결과

| 영역           | 처리한 것                                    | 남긴 것(근거)                                                          | 사용자 실행 필요                                         |
| -------------- | -------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------- |
| ① PRD 아카이브 | login-flow → _archive 이동                   | 없음                                                                   | 없음                                                     |
| ③ tmp          | 14건 삭제, 405MB → 12MB                      | 소켓 5건, 현재 세션, 캐시, 훅 거부 1건                                 | 없음                                                     |
| 메모리         | 자동 메모리 3건 통폐합, docs/memory 2건 편입 | 확인 보류 1건                                                          | 없음                                                     |
| ② 브랜치       | 명령 제시                                    | feat-open (미머지), feat-c (스쿼시 머지라 -d 불가), release/1.2 (버전) | !git branch -d feat-a / !git push origin --delete feat-a |

- git 상태: docs/prds/login-flow → docs/prds/_archive/login-flow 이동, docs/memory 2개 파일 갱신 (커밋 안 함)
- 사용자 실행:

!git branch -d feat-a
!git push origin --delete feat-a
```

브랜치 삭제 명령은 보고 끝에 그대로 다시 적어 바로 붙여넣을 수 있게 한다. 이 명령 줄들이
보고의 끝이다. 그 뒤에 과정 메모 같은 다른 절을 두지 않는다. 사용자가 마지막에 보는 것이 곧
실행할 명령이어야 한다. ② 후보가 없거나 ②를 고르지 않았으면 이 줄은 없다.

## DoD

- 세 영역(또는 지정 영역) 각각에 스캔 근거·보고·컨펌 결과·실행 결과가 있고, 메모리 관리
  결과가 있다. 후보 없음도 명시한다.
- 지운 것은 사용자가 고른 영역 안의 것뿐이고, 제외 요청한 항목은 남아 있다.
- 실행 순서를 지켰다: 메모리 에이전트 호출과 ③ 동시 → ① 완료 후 PRD 이동 → ② 명령 제시 →
  종료.
- 커밋을 만들지 않았고, 스크래치패드에 이 스킬의 임시 파일이 남아 있지 않다.
