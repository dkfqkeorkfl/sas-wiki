`$ARGUMENTS` 에서 선택 인자 `target-path` 를 파싱한다. 빠지면 워크플로우 1에서 묻는다.

본 커맨드는 LLM 의 행동을 통제하는 **행동 지침서** (`CLAUDE.md`, `AGENTS.md` 류) 를 산출한다. 산출물은 README, 명세서, 튜토리얼이 아니다.

## 목적

- 환각·편향·오동작을 방지하는 실제 유효한 지침서를 작성한다.
- LLM 의 행동을 효과적으로 제어한다.
- 상·하위 지침서와의 중복·상충을 사전에 방지한다.

## 입력

- 현재 문서 초안 또는 기존 문서 (대상 파일 존재 시 `Read`).
- 관련 대안 초안·상위 규칙 파일 (있으면 경로를 묻고 `Read`).
- 문서가 반영해야 할 실제 제약·역할·경계·합의.

## 출력

- `CLAUDE.md`, `AGENTS.md` 등의 행동 지침서.
- 「평가 축」에 따른 자체 평가와 개선 사항.

## 워크플로우

1. 작성 의도와 [지침서 유형](#types) 을 파악한다. `target-path` 가 비었으면 이 단계에서 묻는다.
2. [지침서 상관 관계](#relation) 와 필요한 자료를 수집·조사한다. 상·하위 문서가 있으면 `Read` 로 확인한다.
3. 모호·상충·누락 항목을 **한 번에** 모아 사용자에게 질의. 답변 전 초안 작성 금지.
4. 미해결 질의가 남으면 1로 복귀. 모두 해소되면 다음 단계.
5. 「작성·수정 지침」에 따라 행동 지침서를 작성하고 `Write` 로 저장. 기존 파일이 있으면 덮어쓰기 여부를 확인한다.
6. 「평가 축」으로 자체 평가하여 개선 사항과 수정안을 사용자에게 보고한다.

<a id="types"></a>

## 지침서 유형

| 유형                 | 정의                                          | 예                                             |
| -------------------- | --------------------------------------------- | ---------------------------------------------- |
| 범용 지침서          | 조직·도메인 전반에 적용되는 일반 규칙 문서    | `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`    |
| 프로젝트 로컬 지침서 | 특정 프로젝트 내에서만 유효한 규칙 문서       | `{Root}/.claude/CLAUDE.md`, `{Root}/AGENTS.md` |
| 규칙 레이어 문서     | 특정 레이어(언어·계층)에만 적용되는 좁은 규칙 | `~/.claude/rules/*`                            |

<a id="relation"></a>

## 지침서 상관 관계

```text
Global (범용 지침서)
└─ Project (프로젝트 로컬 지침서)   # Global override
   └─ Layer Rules (규칙 레이어 문서) # 조건부 적용 (언어/계층별)
```

- 하위 지침서는 상위 지침서를 override 할 수 있다.
- 동일 범위에서는 더 구체적인 지침이 우선한다.

## 작성·수정 지침

### 1. 과도한 제약을 두지 않는다

LLM 의 문제 해결 능력을 불필요하게 제한하지 않는다.
구체적인 절차나 세부 제약을 과도하게 명시하기보다, **목표와 핵심 기준만 명확히 정의**한다.

- 디테일한 워크플로우는 항상 결과 품질을 높이지 않는다.
- 결과를 좌우하는 **최소한의 기준과 조건만 제시**한다.
- 예: 파일 분류 작업에서는 세부 절차 대신 **분류 기준과 조건**만 정의한다.

---

### 2. 결과에 영향을 끼치는 핵심 사항만 기입한다

모든 지침은 **명확하고 일관된 표현**으로 작성하며 불필요한 내용으로 인한 오동작을 미연에 방지한다.

- 상충된 지시, 모호한 단어, 불명확한 기준은 오동작을 유발한다.
- 의미가 불분명하거나 결과 해석이 달라질 수 있는 표현은 반드시 수정하거나 제거한다.
- 불필요한 부가 설명, 반복 내용, 동작과 무관한 정보는 제외한다.
- **핵심 사항** = 결과 생성에 직접 영향을 주는 기준·의도·제약.
- **불필요한 내용** = 부가 설명·히스토리·메타 설명.

> 원칙: 결과 해석이 단일하게 수렴되도록 작성한다.

---

### 3. 사람과 LLM 모두 이해하기 쉽게 구조화한다

지침서는 LLM 과 사용자가 모두 읽고 활용하는 것을 전제로 한다.

- 사용자는 이 문서를 통해 **프로세스·제약·기준·결과** 를 빠르게 이해할 수 있어야 한다.
- 이해를 돕기 위해 다음 요소를 간결하게 활용한다.
  - 표
  - 리스트
  - 간단한 텍스트 다이어그램
  - 관계도
  - 예
- 문서는 항상 **일관된 구조와 형식** 을 유지한다.

---

### 4. 지침서의 상관 관계를 미리 조사한다

작성하려는 지침서의 상관 관계를 조사하여 중복·상충을 미연에 방지한다.

- 상·하위 지침서가 작성 대상에 미치는 영향도를 조사한다.
- 중복·상충 발견 시 사용자에게 피드백을 요청하여 명확하게 작성한다.
- 작성 내용이 다른 위치에 더 적합하면 그 위치를 제안할 수 있다.

## 평가 축

| 축       | 내용                                                                |
| -------- | ------------------------------------------------------------------- |
| 자율성   | 과도한 제약 없이 문제 해결을 위한 탐색과 판단의 자유를 유지한다.    |
| 견고성   | 환각, 오작동, 의도치 않은 행동을 억제하고 안정적인 출력을 유지한다. |
| 명세성   | 필요한 기능, 조건, 규칙만 서술하고 불필요한 내용을 덧붙이지 않는다. |
| 명확성   | 표현이 모호하지 않으며 해석의 여지가 없다.                          |
| 논리성   | 상충 규칙, 성립 불가 전제, 순환 참조가 없다.                        |
| 객관성   | 검증 가능한 근거와 조건에 기반하여 서술한다.                        |
| 비편향성 | 사용자 요청이나 특정 관점에 과도하게 치우치지 않는다.               |
| 문서품질 | 섹션 배치, 서식 일관성, 참조 정확성이 유지된다.                     |
