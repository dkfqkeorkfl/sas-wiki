# sas-wiki

마크다운 vault(→ [저장소 구조](#저장소-구조) 에서 정의) 와 **git 히스토리**를 입력으로 받아, 위키 화면과 뉴스 피드에 필요한 JSON 을 세 개의 CLI 로 뱉는 데이터 리포지토리다.

서버가 아니다. 빌드 산출물도 없다. `node scripts/<이름>.mjs` 로 실행하면 stdout 에 JSON 한 줄이 나오고 끝난다. 소비자(개발 서버·미래의 실서버)가 필요할 때마다 프로세스를 띄워 그 JSON 을 받아간다.

핵심 아이디어 두 개만 알면 나머지는 따라온다.

1. **문서의 정체성은 경로가 아니라 frontmatter**(문서 맨 위 `---` 로 감싼 YAML 블록)**에 적힌 UUIDv7 `id`** 다. 그래서 문서를 옮기고 이름을 바꾸고 전면 재작성해도 과거 뉴스가 그 문서를 계속 가리킨다.
2. **`feed:` 커밋 하나가 뉴스 카드 하나**다. 뉴스는 별도 파일에 손으로 적는 게 아니라 커밋에서 유도된다. 그래서 피드는 그 자체로 변경 이력이자 감사 추적이 된다.

---

## 빠른 시작

```bash
pnpm install                 # 최초 1회 (런타임 의존성: unified/remark/rehype)

pnpm run summary --env dev   # 화면 뼈대(문서 목록·폴더 트리·태그)
pnpm run feeds --env dev --count 20
pnpm run wiki --env dev --path 'company/삼성전자'
pnpm run validate            # vault 무결성 검사 — --env dev 고정, JSON 대신 exit code 로 말한다
```

`--env dev` 는 초안(draft) 문서까지 전부 보고, `--env prod` 는 초안을 뺀다 — 자세한 건 [dev / prod](#dev--prod).

플래그는 `--` 없이 그대로 이어 붙인다. 이 리포의 pnpm(11.x)은 `--` 를 스크립트에 그대로 넘기는데, 세 스크립트(`summary`·`feeds`·`wiki`)는 위치 인자를 받지 않으므로 `pnpm run summary -- --env dev` 는 `Unexpected argument '--env'` 로 죽는다.

스크립트를 직접 불러도 된다. 결과는 같다.

```bash
node scripts/feeds.mjs --env dev --count 20
```

소비자(개발 서버·미래 서버)는 후자 형태로 부른다. `pnpm run <이름>` 은 소비자와 결합돼 있지 않아 바뀌어도 소비자가 알 수 없는 계약이지만, `node <파일>` 은 파일 경로가 곧 계약이라 깨지면 시끄럽게 깨진다.

## 저장소 구조

```text
vault/wiki/**/*.md      문서 원본. 폴더 구조가 곧 위키의 계층이다
scripts/
  summary.mjs           엔드포인트 — 화면 뼈대
  feeds.mjs             엔드포인트 — 뉴스 피드
  wiki.mjs              엔드포인트 — 문서 1건 본문
  validate.mjs          무결성 검사 CLI (엔드포인트 아님 — JSON 을 안 낸다)
  lib/                  순수 함수 부품 (파싱·git 워크·렌더·불변식)
  schema/               JSON Schema — frontmatter 1종 + 산출물 3종 + 억제목록 1종
ignore-feeds.json       잘못 발행한 피드를 억제하는 목록(tombstone). 아래 피드 발행법 참고
```

용어 두 개를 먼저 못 박는다.

- **vault** — `vault/wiki/` 아래의 마크다운 문서 전체. 이 리포에서 "데이터" 라고 하면 이것이다.
- **엔드포인트** — 소비자가 프로세스로 띄워 JSON 페이로드를 받아가는 세 스크립트(`summary`·`feeds`·`wiki`). `validate` 는 JSON 을 내지 않으므로 엔드포인트가 아니다.

각 엔드포인트 파일은 **순수 함수 export + 얇은 CLI 가드**의 이중 모드다. 함수 export 는 테스트와 리포 내부 재사용을 위한 것이고, **바깥 소비자에게 노출되는 계약은 프로세스 경계(CLI)뿐이다** — 이유는 아래 [누가 이걸 소비하나](#누가-이걸-소비하나) 에 있다. 서빙 로직은 어디에도 없다.

## 데이터 모델

### 문서 — 위키의 단위

문서 하나 = `vault/wiki/` 아래 마크다운 파일 하나. **frontmatter**(문서 맨 위 `---` 로 감싼 YAML 블록)가 메타데이터, 그 아래가 본문이다.

```markdown
---
id: '01088d26-ee68-7a11-b53c-398f328d520e'
title: 삼성전자
type: company
status: active
aliases: ['Samsung', '005930']
tags: ['반도체', '메모리']
meta:
  ticker: '005930'
  sector: '반도체'
  exchange: 'KOSPI'
---

## 개요

삼성전자는 …
```

### 문서 id — 정체성은 경로가 아니다

`id` 는 사람이 직접 적는 **UUIDv7** 이고, 한 번 적으면 절대 바뀌지 않는다. 내용 안에 살기 때문에 이동·이름변경·전면재작성을 모두 견딘다.

id 에는 게이트 세 개가 걸린다.

| 게이트 | 내용                                                                  | 어디서 도는가        |
| ------ | --------------------------------------------------------------------- | -------------------- |
| 형식   | UUIDv7 패턴에 맞아야 한다                                             | `validate` 만        |
| 유일성 | 살아 있는 문서끼리 id 가 겹치면 안 된다 ([불변식](#불변식-8종) 8)     | 엔드포인트 포함 전부 |
| 불변성 | **생성 커밋의 blob 에 적힌 id** 와 현재 frontmatter id 가 같아야 한다 | `validate` 만        |

"`validate` 만" 이라는 오른쪽 칸이 중요하다 — 세 엔드포인트는 대부분의 게이트를 돌지 않는다. 자세한 건 [게이트는 언제 도는가](#게이트는-언제-도는가).

id 체계 이전에 만들어진 문서는 생성 시점에 id 가 없으므로 불변성 게이트를 통과한다(없는 것과 비교하지 않는다).

**지운 경로에 다시 문서를 만들면 그건 복원이 아니라 새 문서다.** 새 id 를 새로 적어야 한다. 경로는 정체성이 아니고, 삭제는 그 문서를 가리키던 피드를 걷어내기(prune) 때문에, 같은 경로에 옛 id 를 다시 쓰면 걷어냈던 이력이 엉뚱한 새 내용 위로 되살아난다. `validate` 가 이걸 별도 게이트로 막는다.

피드 id 와는 폭으로 구분된다 — 문서 id 는 UUIDv7, 피드 id 는 12자리 hex 라 절대 충돌하지 않는다.

시간을 건너뛰는 참조(피드·태그·트리)는 **id** 로, 지금 이 순간의 스냅샷과 URL 은 **현재 경로**로 가리킨다.

### 계층 — 폴더가 곧 경로다

문서의 위치는 frontmatter 에 적지 않는다. 폴더 구조에서 유도한다.

```text
vault/wiki/company/삼성전자.md
        → breadcrumb = ["company", "삼성전자"]
        → path       = "company/삼성전자"   (breadcrumb.join('/'))
```

**문서**의 계약에는 문자열 `path` 필드가 없다 — summary 의 `docs[]` 를 봐도 `breadcrumb` 뿐이고, 경로는 거기서 만든다. (`tree[]` 는 문서가 아니라 폴더 노드라 `path` 를 직접 갖는다. wiki 응답의 `path` 는 요청에 쓴 ref 를 그대로 돌려주는 에코다.)

### 피드 — 커밋 하나가 뉴스 하나다

`feed:` 로 시작하는 커밋 하나가 뉴스 카드 하나가 된다. 커밋 제목이 헤드라인, 본문이 카드 본문, 그 커밋이 건드린 문서들이 "관련 문서" 칩이 된다.

뉴스를 별도 파일로 관리하지 않는 이유: 그렇게 하면 "무엇이 바뀌었나"(git)와 "무엇이 뉴스인가"(파일)가 따로 놀다가 반드시 어긋난다. 커밋에서 유도하면 둘이 구조적으로 같은 것이 된다.

피드가 문서를 가리킬 때는 **그 커밋 시점의 경로**를 git rename 추적으로 따라가 현재 문서 id 로 해석한다. 그래서 문서를 옮겨도 과거 뉴스가 살아 있다.

## CLI

### 공통 계약

네 스크립트가 모두 지키는 규약이다.

| 항목      | 계약                                                                |
| --------- | ------------------------------------------------------------------- |
| 성공 출력 | **stdout 에 JSON 한 줄** + 개행 (validate 제외)                     |
| 실패 출력 | stderr 에 에러 메시지, **exit 1**                                   |
| `--vault` | 생략하면 **이 스크립트가 속한 리포 루트**. 현재 디렉토리와 무관하다 |
| `--env`   | `dev` \| `prod`. 생략하면 `prod`                                    |
| 위치 인자 | 받지 않는다. 전부 이름 있는 플래그다                                |

`--vault` 기본값은 cwd 폴백이 아니라 `import.meta.url` 에서 유도한다. 어디서 부르든 자기 리포를 읽으므로 엉뚱한 디렉토리를 파싱하는 사고가 나지 않는다. 다른 vault 를 읽으려면 명시적으로 `--vault <경로>` 를 준다.

`--env` 는 **fail-closed** 다. 세 엔드포인트에서 `dev` 가 아닌 모든 값(미지정·`prod`·오타·빈 문자열)은 prod 로 떨어진다. 즉 실수하면 더 많이 보이는 쪽이 아니라 **더 적게 보이는 쪽**으로 잘못된다. (`validate` 만 예외적으로 더 엄격하다 — 아래 참고.)

### summary

화면 뼈대. 사이드바 트리·태그·검색 색인·필터에 필요한 것만 담고 **본문은 담지 않는다**.

```bash
node scripts/summary.mjs [--vault <dir>] [--env dev|prod]
```

### feeds

뉴스 피드. 최신순 정렬·억제 반영·커서 페이징까지 여기서 끝난다.

```bash
node scripts/feeds.mjs [--vault <dir>] [--env dev|prod]
                       [--count <n>] [--after <cursor-json>]
                       [--from <ISO>] [--to <ISO>]
```

| 플래그    | 기본값 | 의미                                                         |
| --------- | ------ | ------------------------------------------------------------ |
| `--count` | `50`   | 페이지 크기. 0 이하·미지정이면 50                            |
| `--after` | 없음   | 커서. 반환값의 `nextCursor` 를 **JSON 문자열 그대로** 넘긴다 |
| `--from`  | 없음   | 이 시각 이후(포함). ISO 날짜                                 |
| `--to`    | 없음   | 이 시각 이전(포함). ISO 날짜                                 |

```bash
# 1페이지 → items: bd8bf74279b0, 4eb6ee1c9d6b
#           nextCursor: {"feedId":"4eb6ee1c9d6b","ts":"2006-01-02T22:17:05Z"}
node scripts/feeds.mjs --env dev --count 2
# 2페이지 — 1페이지 응답의 nextCursor 를 그대로 넘긴다 → items: 0192a9222428, eca3be1e87bd
node scripts/feeds.mjs --env dev --count 2 --after '{"feedId":"4eb6ee1c9d6b","ts":"2006-01-02T22:17:05Z"}'
```

`--from`/`--to` 는 문자열 비교가 아니라 epoch 로 정규화해 비교한다(`+09:00` 같은 오프셋이 섞여도 안전하다). 파싱 불가한 값을 주면 조용히 전량 통과시키지 않고 에러로 끊는다.

정렬은 **author-date 내림차순, 동률이면 id 오름차순**으로 결정적이다.

### wiki

문서 1건. 본문은 여기서만 나온다(지연 로드).

```bash
node scripts/wiki.mjs [--vault <dir>] [--env dev|prod] --path <경로>
```

`--path` 는 `breadcrumb.join('/')` 형태다 — 확장자도, `vault/wiki/` 접두사도 붙이지 않는다.

```bash
node scripts/wiki.mjs --env dev --path 'company/삼성전자'
```

### validate

vault 무결성 검사 전용. **JSON 을 생산하지 않는다.** 페이로드를 메모리에서만 조립해 게이트를 전량 돌리고, 통과하면 exit 0, 위반하면 사유를 출력하고 exit 1 로 죽는다.

```bash
node scripts/validate.mjs [--vault <dir>] [--env dev|prod] [--schema <dir>] [--deadlinks ignore|warn|error]
```

| 플래그           | 의미                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| `--env`          | 미지정 시 prod + **stderr 경고**. 알 수 없는 값은 에러로 끊는다       |
| `--schema`       | 스키마 디렉토리 override (기본 `scripts/schema`)                      |
| `--deadlinks`    | 데드링크 심각도. `ignore`, `warn`(기본), `error` 중 하나              |
| `--help` `-h`    | 사용법 출력                                                           |
| `--out` `--root` | **제거됨**. 넘기면 에러로 끊는다 (JSON 을 안 만드니 출력 인자도 없다) |

> `pnpm run validate` 는 **`--env dev` 가 박혀 있다.** prod 를 검증하려면 `node scripts/validate.mjs` 를 직접 부른다. 둘은 결과가 크게 다르다 — 이 리포의 예제 vault 는 전량 draft 라 prod 에서는 `docs=0` 이 나온다.

돌리는 게이트: 커밋 컨벤션 → frontmatter 스키마 + id 불변성 → 데드링크 → 피드 해석 실패 → 떠돌이 파일 → 삭제된 id 재사용 → 산출물 스키마(strict) → [불변식 8종](#불변식-8종).

출력은 JSON 이 아니라 요약 한 줄이다.

```text
[wiki] docs=6 body=5 feeds=5 prune=1 prunedFeeds=1 unresolved=0 warnings=0
```

경고가 있으면 그 아래로 항목별 줄이 더 붙는다(`[wiki]   off-convention: <sha12> "<제목>"`, `[wiki]   warning: <sha12> <사유>`). **출력을 한 줄로 가정하고 파싱하지 마라.** `warnings` 는 실패가 아니다 — exit code 에 영향을 주지 않는다.

`prune` = 삭제·draft 배제로 걷어낸 피드 참조 수, `prunedFeeds` = 참조가 전부 걷혀 통째로 사라진 피드 수. 이 숫자가 갑자기 튀면 rename 추적이 깨졌다는 신호이므로 0 이어도 항상 찍는다. (위 숫자는 이 리포 예제 vault 의 `--env dev` 실측값이라 vault 상태에 따라 달라진다.)

### 게이트는 언제 도는가

**자동으로 도는 게 아니다.** 이 리포에는 pre-commit 훅도 CI 도 없고, 세 엔드포인트는 위에 열거한 검증 게이트를 돌리지 않는다 — vault 를 파싱해 그대로 투영할 뿐이다.

그래서 id 를 사후 변조한 커밋이 있어도 `summary`·`feeds` 는 **exit 0 으로 오염된 데이터를 그대로 뱉는다.** 잡는 것은 `validate` 뿐이고, 그건 **누군가 직접 실행해야** 돈다.

다만 엔드포인트도 무조건 살아 나오지는 않는다. 파싱 자체가 불가능한 상태에서는 exit 1 로 죽는다. 대표적으로는:

| 엔드포인트도 죽는 조건                  | 어디에 설명이 있나                                                                |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| 문서 id 중복                            | [불변식](#불변식-8종) 8 — 유일성만 전 경로 검사                                   |
| 생성 커밋 없음(미커밋 문서)             | [저장만으로는 아무 일도 일어나지 않는다](#저장만으로는-아무-일도-일어나지-않는다) |
| shallow·partial clone, git 자체가 없음  | [클론 요건](#클론-요건)                                                           |
| `ignore-feeds.json` 파싱·스키마 위반    | [잘못 발행한 피드 되돌리기](#잘못-발행한-피드-되돌리기)                           |
| frontmatter 구조가 깨짐(`type` 부재 등) | —                                                                                 |
| 한 문서 안에 중복 블록 id               | —                                                                                 |
| `--after` 커서에 `ts`·`feedId` 가 빠짐  | [feeds](#feeds)                                                                   |

**주의 — 방향이 직관과 반대인 경우가 있다.** frontmatter 가 _깨진_ 문서는 엔드포인트를 죽이지만, frontmatter 가 **아예 없는** 파일은 조용히 건너뛴다. 그 문서만 소리 없이 사라지고 나머지는 정상 응답한다. 이런 "떠돌이 파일" 은 `validate` 만 잡는다.

`validate` 에서만 걸리는 것: id 형식·id 불변성·frontmatter 스키마 전반(`type`·`status` enum, `company` 의 `meta` 필수, `created`/`updated` 금지)·커밋 컨벤션·데드링크·피드 해석 실패·떠돌이 파일·삭제된 id 재사용·앵커 정합·응답 스키마 strict·[불변식](#불변식-8종) 1~7.

> 문서를 고치거나 피드를 발행한 뒤에는 커밋을 밀기 전에 `pnpm run validate` 를 돌린다. 이게 이 리포의 유일한 안전망이다.

## 반환 데이터형

세 엔드포인트의 반환값을 하나씩 본다. 예시는 이 리포의 예제 vault 를 `--env dev` 로 돌린 **실제 출력**이며, 길면 `…` 로 줄였다. (한 곳만 예외 — wiki 의 `sources` 는 예제 vault 에 각주가 하나도 없어 실제로는 `[]` 라, 거기만 형상 예시다.)

summary 와 feeds 는 같은 `sourceCommit`(= 그 응답을 만든 커밋의 40자 해시, **세대 식별자**)을 가질 때만 한 세트다. 세대가 섞이면 참조가 조용히 깨지므로 소비자는 반드시 같은 세대끼리 묶어 쓴다. wiki 응답에는 `sourceCommit` 이 없으므로 세대 대조는 summary·feeds 로 한다.

### summary 반환값

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-07-23T05:11:49.000Z",
  "sourceCommit": "5e3efb0071149ccb5e507cf2a1d5c2fff2a00546",
  "docs": [/* … */],
  "tree": [/* … */],
  "tags": {/* … */},
}
```

| 키              | 타입                 | 설명                                                                                                                                                                                           |
| --------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | `number`             | 계약 버전. 파괴적 교체에만 +1 (필드 추가로는 안 올린다)                                                                                                                                        |
| `generatedAt`   | `string`             | **실행 시각이 아니다.** 가장 최근 문서 `updated`/피드 `ts` 에서 유도한 결정적 값(`SOURCE_DATE_EPOCH` 가 있으면 그것). vault 가 그대로면 몇 번을 돌려도 같은 값이라 신선도·캐시 키로 쓸 수 없다 |
| `sourceCommit`  | `string`             | 이 응답을 만든 커밋의 40자 해시. **세대 식별자**                                                                                                                                               |
| `docs`          | `SummaryDoc[]`       | 문서 목록. status 로 모양이 갈린다                                                                                                                                                             |
| `tree`          | `TreeNode[]`         | 폴더 트리 (재귀)                                                                                                                                                                               |
| `tags`          | `Record<태그, id[]>` | 태그 → 문서 id 역색인. active 문서만                                                                                                                                                           |

**`docs[]` — status 로 갈리는 유니온.**

active 문서는 10키다.

```jsonc
{
  "id": "01088d26-ee68-7a11-b53c-398f328d520e",
  "breadcrumb": ["company", "삼성전자"],
  "title": "삼성전자",
  "status": "active",
  "type": "company", // concept | company | moc
  "tags": ["반도체", "메모리"],
  "aliases": ["Samsung", "005930"], // 검색용 별칭
  "excerpt": "삼성전자는 메모리·시스템 반도체와 …", // 본문 첫 문단 요약
  "created": "2006-01-02T22:05:05Z", // git 이 아는 생성 커밋 시각
  "updated": "2026-07-23T14:11:49+09:00", // 마지막 수정 커밋 시각
}
```

`status: "disable"` 문서는 **4키 스텁**만 남는다. 본문은 지우되 링크는 살려두기 위해서다 — 과거 피드나 위키링크가 이 문서를 가리키고 있어도 제목만은 보여줄 수 있다.

```jsonc
{
  "id": "01088d2a-97e8-7dcd-808d-3b7f9180fa79",
  "breadcrumb": ["concept", "온디바이스-AI"],
  "title": "온디바이스 AI",
  "status": "disable",
}
```

`created`/`updated` 는 frontmatter 에 적는 게 아니라 git 히스토리에서 유도한다. 적으면 검증이 거부한다.

**`tree[]` — 폴더 노드.**

```jsonc
[
  { "path": "company", "docs": ["01088d27-…", "01088d28-…", "01088d26-…"], "children": [] },
  { "path": "moc", "docs": ["01088d2c-…"], "children": [] },
  { "path": "tech", "docs": ["01088d29-…"], "children": [] },
]
```

`docs` 에는 **active 문서 id 만** 들어간다. 그래서 disable 문서만 있는 폴더는 노드 자체가 없다(이 리포의 예제 vault 에서 `concept` 이 트리에 없는 이유다). `path` 는 항상 그 문서들의 `breadcrumb.slice(0, -1).join('/')` 와 일치한다.

**`tags`**

```jsonc
{
  "메모리": ["01088d27-…", "01088d26-…", "01088d29-…"],
  "반도체": ["01088d27-…", "01088d28-…", "01088d26-…", "01088d2c-…"],
  "파운드리": ["01088d28-…"],
  "AI": ["01088d29-…"],
}
```

태그의 정본은 문서 frontmatter 다. 피드에는 태그가 없다(피드는 `keywords` 를 따로 갖는다).

### feeds 반환값

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-07-23T05:11:49.000Z",
  "sourceCommit": "5e3efb00…",
  "items": [/* … */],
  "nextCursor": null,
}
```

**`items[]` — 정확히 7키.**

```jsonc
{
  "id": "fdabfe65a127", // 커밋 해시 앞 12자리
  "ts": "2006-01-02T22:12:05Z", // author date
  "title": "삼성전자, HBM3E 12단 양산 승인", // 커밋 제목의 "feed: " 뒤
  "body": "삼성전자가 HBM3E 12단 제품의 양산 승인을 획득했다. 하반기 공급이 시작된다.", // 커밋 본문(트레일러 줄 제외 — 아래 피드 발행법)
  "keywords": ["HBM", "양산", "삼성전자"], // Keywords: 트레일러
  "importance": "breaking", // normal | highlight | breaking
  "docs": [{ "id": "01088d26-ee68-7a11-b53c-398f328d520e", "anchor": null, "anchorText": null }],
}
```

**`docs[]` — 이 커밋이 고친 문서.**

| 키           | 타입             | 설명                                                           |
| ------------ | ---------------- | -------------------------------------------------------------- |
| `id`         | `string`         | 문서 id. **경로가 아니다** — 문서가 이동해도 안 깨진다         |
| `anchor`     | `string \| null` | 변경이 걸린 heading 의 URL 슬러그. **현재 항상 `null`** — 아래 |
| `anchorText` | `string \| null` | 그 heading 의 표시용 원문(카드 점프 칩 라벨). 동상             |

> **앵커는 현재 채워지지 않는다.** 계약과 스키마에는 `anchor`·`anchorText` 가 있고 `validate` 쪽 파생 경로에는 유도 로직(diff hunk 를 heading 구간에 매핑)이 구현돼 있지만, `feeds` 엔드포인트가 쓰는 경로는 두 값을 항상 `null` 로 넣는다. 예제 vault 의 피드 5건·문서 참조 6건 전부 `null` 이다. 소비자는 `anchor` 를 **선택적 값으로 다뤄야** 하며, 점프 칩은 문서 단위로만 만들 수 있다.

`anchorText` 가 문서 본문에만 있는 정보인데도 피드 쪽에 자리를 잡고 있는 이유: 피드 화면이 라벨 하나 때문에 본문 페이로드를 당겨오면 "부팅 페이로드에 본문 없음" 이라는 설계가 무너지기 때문이다. 그래서 값이 채워질 때는 비정규화해 싣는다.

`anchor` 가 `null` 이면 `anchorText` 도 반드시 `null` 이다([불변식](#불변식-8종) 6).

**`nextCursor` — 커서 페이징.**

```jsonc
{ "ts": "2026-01-02T22:13:05Z", "feedId": "eca3be1e87bd" }
```

다음 페이지가 있을 때만 값이 있고, 마지막 페이지면 `null` 이다. 값은 **이번 페이지 마지막 항목**의 좌표이며, 그대로 다음 호출의 `--after` 에 넣으면 된다. 오프셋이 아니라 (시각, id) 좌표라서 그 사이에 피드가 늘어도 밀리거나 중복되지 않는다.

### wiki 반환값

`--path` 가 무엇을 가리키느냐에 따라 셋 중 하나다.

**① active 문서 — 7키.**

```jsonc
{
  "path": "company/삼성전자",
  "breadcrumb": ["company", "삼성전자"],
  "status": "active",
  "html": "<h2 id=\"개요\">개요</h2>\n<p>…</p>",
  "headings": [
    { "anchor": "개요", "level": 2, "text": "개요" },
    { "anchor": "사업-부문", "level": 2, "text": "사업 부문" },
    { "anchor": "메모리-로드맵", "level": 2, "text": "메모리 로드맵" },
  ],
  "meta": { "ticker": "005930", "sector": "반도체", "exchange": "KOSPI" },
  "sources": [{ "label": "…", "text": "…" }],
}
```

| 키         | 설명                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| `html`     | 렌더 완료된 본문. 위키링크는 `<a class="wiki-link" data-path="…">` 로 나온다 |
| `headings` | 목차·앵커 검증용. `anchor` 는 URL 슬러그, `text` 는 표시용 원문              |
| `meta`     | frontmatter 의 자유 필드 — 인포박스에 그대로 쓰인다                          |
| `sources`  | 본문의 **각주 정의**(`[^라벨]: 내용`)를 모은 것. 없으면 `[]`                 |

마크다운 원문(`md`)·백링크는 계약에 없다. 소비처가 없어서 뺐다.

**주의**: 이 응답에는 `id` 가 없다. 문서 id 가 필요하면 summary 의 `docs[]` 에서 `breadcrumb` 으로 찾는다.

**② disable 문서 — summary 스텁 4키 그대로.** `id`·`breadcrumb`·`title`·`status`.

**③ 없는 경로 — `null`.** 에러가 아니라 `null` 이 stdout 에 찍히고 exit 0 이다.

## 문서 작성법

`vault/wiki/<폴더>/<문서명>.md` 를 만들고 frontmatter 를 채운다.

| 필드      | 필수 | 값                                                        |
| --------- | ---- | --------------------------------------------------------- |
| `id`      | ✔    | UUIDv7. 직접 생성해 적고 **이후 절대 변경 금지**          |
| `title`   | ✔    | 표시 제목                                                 |
| `type`    | ✔    | `concept` \| `company` \| `moc`                           |
| `status`  | ✔    | `active` \| `disable`                                     |
| `aliases` |      | 검색용 별칭 배열 (영문명·티커 등)                         |
| `tags`    |      | 태그 배열                                                 |
| `meta`    |      | 자유 객체 → 인포박스                                      |
| `draft`   |      | dev 전용 표식(불리언). 아래 [dev / prod](#dev--prod) 참고 |

`type: company` 는 `meta.ticker`·`meta.sector`·`meta.exchange` 가 **필수**다(값이 `null` 인 건 허용).

id 는 이렇게 만든다. `uuid` 는 이 리포의 devDependency 라 **리포 루트에서 `pnpm install` 을 한 뒤** 리포 안에서 실행해야 한다.

```bash
node -e "console.log(require('uuid').v7())"
```

`created`·`updated` 는 **적지 않는다.** git 히스토리에서 유도하며, 적혀 있으면 검증이 거부한다.

> **예제 브랜치(`test`)에 문서를 추가한다면 `draft: true` 를 반드시 함께 적는다.** 예제 vault 의 문서는 전부 draft 이고, 새 문서만 draft 없이 들어가면 그 문서만 prod 에 남는다. 그 상태에서 예제 문서로 위키링크를 걸면 prod 검증이 "대상 문서 없음" 데드링크로 죽는다 — 파일은 멀쩡히 있는데 없다고 나오므로 원인을 찾기 매우 어렵다.

### 저장만으로는 아무 일도 일어나지 않는다

새 `.md` 를 만들고 저장한 직후에 CLI 를 돌리면 **세 엔드포인트가 전부 exit 1 로 죽는다.**

```text
생성 커밋을 찾을 수 없습니다: vault/wiki/tech/CXL.md
```

frontmatter 를 틀린 게 아니다. `created` 를 git 에서 유도하는데 생성 커밋이 아직 없어서다. **`cwiki` 로 커밋해야 문서가 존재하기 시작한다.**

```bash
git add vault/wiki/tech/CXL.md
git commit -m "cwiki: CXL 문서 추가"
```

**생성 커밋에 틀린 id 를 적었다면** amend 하지 마라(히스토리 재작성 금지). 불변성 게이트가 생성 커밋의 blob 과 대조하므로 그 문서는 영구히 `validate` 실패 상태가 된다. 복구는 **삭제 커밋(`uwiki`) → 새 id 로 다시 `cwiki`** 다. 옛 id 는 재사용하지 않는다.

### 각주 = 출처

본문에 마크다운 각주 정의를 쓰면 wiki 응답의 `sources[]` 가 된다. frontmatter 가 아니라 본문이다.

```markdown
자세한 규격은 공개 문서에 있다[^spec].

[^spec]: CXL Consortium, CXL 3.1 Specification (2023)
```

각주 정의 줄은 `sources[]` 로 **복사될 뿐 `html` 에서 제거되지 않는다.** 마커(`[^spec]`)와 정의 줄이 렌더된 본문에 그대로 남으므로, 정의는 본문 맨 아래에 모아 두고 표시는 소비자 쪽에서 처리하는 것을 전제로 한다.

### 위키링크

문서끼리는 `[[대상]]` / `[[대상#앵커]]` 로 잇는다.

- **대상** = 전체 경로(`company/삼성전자`) 또는 **문서 파일명**(`삼성전자`). 파일명이 유일하지 않으면 "동명 문서 충돌" 로 잡힌다.
- **`aliases` 는 링크 대상이 아니다.** `[[Samsung]]` 은 데드링크다 — aliases 는 검색용이다.
- **앵커는 URL 슬러그로 적는다**(`[[삼성전자#메모리-로드맵]]`). heading 원문 그대로(`#메모리 로드맵`) 써도 `validate` 는 통과하지만 슬러그로 정규화되지 않아 실제 점프가 깨진다.

대상이나 앵커가 없으면 `validate` 가 데드링크로 잡는다.

## 피드 발행법

### 커밋 컨벤션

vault 를 건드리는 커밋은 세 종류 중 하나여야 한다.

| 타입    | 뜻                                        | 파일 규칙                              | 피드 발행 |
| ------- | ----------------------------------------- | -------------------------------------- | --------- |
| `cwiki` | 새 문서 하나를 만든다                     | 새 `.md` **정확히 1개** + **삭제 0개** | 아니오    |
| `uwiki` | 문서를 고치거나 삭제·이동한다 (뉴스 아님) | 기존 파일만 — **새 파일 추가 0개**     | 아니오    |
| `feed`  | 문서를 고치고 뉴스를 낸다                 | 기존 파일만 — **새 파일 추가 0개**     | **예**    |

**이 파일 규칙을 어기면 경고가 아니라 `validate` 실패다**(exit 1). 이동·이름변경은 새 파일 추가로 세지 않으므로 `uwiki`(또는 뉴스도 낼 거면 `feed`) + `git mv` 로 커밋한다.

`cwiki` 가 문서 하나로 제한되는 이유: 문서마다 생성 커밋이 하나씩 대응해야 감사 추적이 읽히고, 피드 유도와 rename 추적이 그 전제 위에 서 있다.

vault 밖만 건드리는 커밋(`chore`·`ci`·`docs` 등)은 이 규약 대상이 아니다. vault 를 건드리면서 세 타입 중 어느 것도 아니면 `off-convention` 으로 집계된다(경고, exit 0). **단 그런 커밋이 vault 문서 추가와 삭제를 동시에 담으면 접두어와 무관하게 실패한다** — 이동+전면재작성을 한 커밋에 몰아넣어 git 이 rename 을 놓치는 사고를 막는 가드다.

### feed 커밋 메시지 → 피드 필드

```text
feed: 삼성전자 HBM3E 양산 승인

삼성전자가 HBM3E 12단 제품의 양산 승인을 획득했다. 하반기 공급이 시작된다.

Keywords: HBM, 양산
Importance: breaking
```

| 커밋의 무엇               | 피드의 무엇                          |
| ------------------------- | ------------------------------------ |
| 커밋 해시 앞 12자리       | `id`                                 |
| author date               | `ts`                                 |
| `feed: ` 뒤 제목          | `title`                              |
| 본문(트레일러 제외)       | `body`                               |
| `Keywords:` 트레일러      | `keywords[]`                         |
| `Importance:` 트레일러    | `importance`                         |
| diff 가 건드린 vault 문서 | `docs[].id`                          |
| diff hunk ↔ heading 매핑  | `docs[].anchor`, `docs[].anchorText` |

### 트레일러 규칙

트레일러 인식 규칙이 조금 까다로우니 정확히 알아두는 게 좋다.

- 커밋 본문의 **마지막 빈 줄 이후 블록 전체**가 후보다.
- 그 블록의 **모든 줄**이 `Key: value` 형태여야 트레일러로 인정된다. 한 줄이라도 아니면 **트레일러 0개**로 처리되고, 그 줄들은 그냥 본문(`body`)에 남는다.
- 키는 대소문자를 구분하지 않는다(`keywords:` 도 된다).
- `Keywords` 는 콤마로 나눈다. 공백은 다듬고 빈 항목은 버린다.
- `Importance` 는 `breaking` \| `highlight` \| `normal` 만 허용(대소문자 무관). 다른 값을 쓰면 `normal` 로 떨어지고 **경고로 집계**된다 — 조용히 무시하지 않는다. 트레일러가 아예 없으면 `normal`.

즉 트레일러 블록 앞에는 **반드시 빈 줄**이 있어야 하고, 그 블록에 산문을 섞으면 안 된다.

### 앵커 — 지금은 붙지 않는다

`docs[].anchor` 는 손으로 적는 값이 아니다. 설계상으로는 그 커밋의 diff hunk 가 문서의 어느 heading 구간에 걸쳐 있는지 줄 단위로 세어 **가장 많이 걸친 heading** 을 고르게 되어 있고, 그 유도 로직은 `validate` 가 쓰는 파생 경로에 구현돼 있다.

유도는 실제로 동작한다 — 이 리포의 예제 vault 에서도 문서 참조 6건 중 4건에 앵커가 붙는다(3종: `메모리-로드맵` 2건, `메모리-사업`, `공급망`). 불변식 6 이 검사하는 것도 그 값이다.

**문제는 `feeds` 엔드포인트가 그 결과를 쓰지 않는다는 것이다 — 응답은 항상 `null` 이다.** 유도는 공유 파싱 엔진에서 `feeds` 호출 때도 매번 돌지만, 엔드포인트는 그 산출물을 버리고 앵커를 넣지 않는 별도 피드 워커의 결과를 응답으로 쓴다. 그래서 섹션 하나만 고치는 커밋으로 나눠도 응답은 달라지지 않는다.

따라서 지금 시점의 실무 규칙은 이렇다.

- 소비자는 `anchor` 를 **항상 `null` 일 수 있는 값**으로 다룬다. 피드 카드의 점프는 문서 단위로만 만들 수 있다.
- 커밋을 섹션 단위로 쪼개도 피드 응답의 앵커는 생기지 않는다. 다른 이유(가독성·되돌리기)로 쪼개는 건 여전히 좋다.

### 잘못 발행한 피드 되돌리기

**히스토리를 다시 쓰지 않는다.** rebase·squash·amend·force-push 는 이 리포에서 금지다 — 커밋 해시가 곧 피드의 정체성이라 히스토리를 손대면 과거 피드가 통째로 뒤틀린다.

대신 `ignore-feeds.json` 에 묘비(tombstone)를 추가해 **억제**한다. 억제는 삭제가 아니다 — 원본 커밋과 문서는 그대로 남고 피드 출력에서만 빠진다. 커밋 없이 파일 저장만으로 즉시 반영된다.

`ignore-feeds.json` 은 **주석을 허용하지 않는 표준 JSON** 이다. 주석을 넣으면 세 엔드포인트가 전부 파싱 에러로 죽는다.

```json
[
  {
    "id": "fdabfe65a127",
    "when": "2026-07-25T14:30:00Z",
    "reason": "수치 오기 — 정정 피드로 대체",
    "by": "shlee"
  }
]
```

| 필드     | 필수 | 값                                                             |
| -------- | ---- | -------------------------------------------------------------- |
| `id`     | ✔    | 억제할 피드 id (= 커밋 해시 앞 12hex)                          |
| `when`   | ✔    | 억제 시각. RFC3339 date-time — `2026-07-25` 처럼 날짜만은 거부 |
| `reason` |      | 억제 사유. 선택이지만 강력 권장 (감사 추적)                    |
| `by`     |      | 억제한 사람                                                    |

## dev / prod

`--env` 는 **draft 문서를 보여줄지**를 결정한다. `dev` 는 전부, `prod` 는 draft 를 뺀다.

문서가 draft 인 판정은 **OR** 다 — 신호가 하나라도 있으면 숨긴다.

| 신호        | 조건                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| frontmatter | `draft` 가 있고 값이 `false` 가 아니면 draft. 즉 `draft: yes` 같은 오타도 숨긴다 |
| 경로        | 문서 경로가 `dev` 이거나 `dev/` 아래면 draft (`develop/` 는 해당 없음)           |

`draft` 에는 `true`/`false` 만 쓴다. 불리언이 아닌 값은 엔드포인트가 숨겨 주긴 하지만(누출은 없다), `validate --env dev` 가 스키마 위반으로 죽인다(`draft` 는 boolean 타입). **prod 검증으로는 이 오타를 못 잡는다** — prod 는 draft 문서를 스키마 검사 _전에_ 빼버리기 때문이다.

두 신호를 AND 가 아니라 OR 로 묶은 이유는 방향 때문이다. 플래그를 깜빡해도 폴더가 잡고, 폴더를 안 써도 플래그가 잡는다. 오타로 **숨는** 사고는 눈에 띄어 금방 고쳐지지만, 오타로 **새는** 사고는 되돌릴 수 없다.

draft 문서는 검증·파생·데드링크 검사보다 **먼저** 제거된다. 그래서 어떤 페이로드에도 흔적이 남지 않는다. draft 문서를 가리키던 피드는 삭제와 같은 방식으로 걷어내고(부재의 사유가 설명되므로 "해석 실패" 로 세지 않는다), 한 피드가 draft 문서와 공개 문서를 함께 가리키면 공개 쪽만 남는다.

dev → prod 승격은 어떤 신호로 숨겼느냐에 따라 다르다.

- **플래그로 숨긴 문서** — `draft` 를 지우면 끝이다. id 도 경로도 바뀌지 않는다.
- **`dev/` 폴더로 숨긴 문서** — 폴더 밖으로 옮겨야 한다. id 는 그대로지만 **경로가 바뀐다**(= URL 과 wiki `--path` 가 바뀐다). 이동은 `uwiki` + `git mv` 로 커밋한다.

## 규칙과 불변식

### 브랜치 정책

| 브랜치          | 용도          |
| --------------- | ------------- |
| `main`          | 서비스 데이터 |
| `test`·`test-*` | 예제 데이터   |

**예제 히스토리를 서비스 브랜치에 머지하지 않는다.** 파이프라인은 예제 `feed:` 커밋과 진짜 `feed:` 커밋을 구분할 방법이 없다. 한번 섞이면 가짜 뉴스가 서비스 피드에 영구히 남는다.

staging 성격의 브랜치를 따로 두더라도 마찬가지다 — **예제 히스토리와 분리 상태를 유지**해야 한다.

### 클론 요건

입력은 `vault/wiki/**/*.md` **와 전체 git 히스토리** 둘 다다.

| 입력              | 쓰임                                                         |
| ----------------- | ------------------------------------------------------------ |
| 마크다운 파일     | 현재 내용과 frontmatter (저작된 UUIDv7 `id` 포함)            |
| 전체 git 히스토리 | 생성·수정 시각, 피드, rename 추적, 삭제 반영, id 불변성 검사 |

**shallow clone 과 partial clone 은 유효한 입력이 아니다.** shallow 는 생성 커밋을 가려 날짜와 피드를 조용히 바꾸고, partial 은 검증에 필요한 blob(불변성 게이트가 읽는 생성 시점 frontmatter)을 가린다. 검출되면 응답을 내기 전에 실패한다.

### 불변식 8종

`validate` 가 강제한다. 위반하면 exit 1 로 죽는다. 엔드포인트는 **8번(id 유일성)만** 검사하고 나머지 1~7 은 돌리지 않는다 — [게이트는 언제 도는가](#게이트는-언제-도는가).

아래 표의 `summary`·`feeds` 는 같은 이름의 엔드포인트 응답이고, **`body` 는 `validate` 가 메모리에서만 조립하는 내부 페이로드**다(키 = active 문서의 현재 경로, 값 = 그 문서의 본문 4키). wiki 엔드포인트가 문서 1건씩 잘라 주는 것이 이 `body` 의 한 조각이다.

| #   | 불변식                                                                                      | 깨지면 생기는 일                     |
| --- | ------------------------------------------------------------------------------------------- | ------------------------------------ |
| 1   | 모든 `feeds.items[].docs[].id` 가 `summary.docs[].id` 에 존재한다 (disable 스텁 포함)       | 피드 카드가 제목·태그·점프를 잃는다  |
| 2   | `body.docs` 의 키 집합 = active 문서의 현재 경로 집합                                       | 문서를 눌러도 본문이 없다            |
| 3   | `tree[].docs[]` 는 active id 만 담고, 모든 active 문서는 정확히 한 노드에 속한다            | 사이드바 행이 비거나 사라진다        |
| 4   | `tags[*]` 는 active id 만 담는다                                                            | 태그 페이지가 비거나 개수가 오염된다 |
| 5   | `tree[].path` = 그 문서들의 `breadcrumb.slice(0, -1).join('/')`                             | 서브트리 필터가 엉뚱한 문서를 낸다   |
| 6   | 피드의 각 앵커는 `null` 이거나 그 문서의 현재 heading 에 존재하고, `anchorText` 가 일치한다 | 점프가 실패하거나 라벨이 틀린다      |
| 7   | 세 페이로드(summary·feeds·body)의 `sourceCommit` 이 같고, 한 세트로만 소비된다              | 세대가 섞여 참조가 조용히 깨진다     |
| 8   | `summary.docs[].id` 가 유일하다                                                             | 참조가 엉뚱한 문서로 간다            |

여기에 더해 응답은 **strict** 로 검증한다. 계약에서 사라진 필드가 하나라도 남아 있으면 실패다 — 파이프라인 버그를 조용히 흘려보내지 않기 위해서다.

삭제된 문서는 피드 참조에서 걷어내고(prune), 한 피드의 참조가 전부 걷히면 그 피드도 사라진다. 걷어낸 개수는 `validate` 가 항상 보고한다 — 갑작스러운 급증은 rename 추적이 깨졌다는 신호다.

## 누가 이걸 소비하나

현재 소비자는 **sas-webfront 의 개발 서버**다. Vite dev 미들웨어가 이 스크립트들을 자식 프로세스로 띄워 stdout JSON 을 파싱한다. 모듈로 `import` 하지 않는다.

프로세스 경계를 계약 경계로 잡은 이유는 미래 때문이다. 실서버는 Rust 로 만들 예정이고, Rust 는 node 모듈을 import 할 수 없다 — CLI 나 HTTP 로만 부를 수 있다. 지금 개발 서버가 CLI 로 소비해두면 그 통합을 미리 연습하는 셈이고, stdout JSON 은 순수 함수의 반환값과 같은 모양이라 나중에 HTTP 로 승격해도 계약이 흔들리지 않는다.

소비자 쪽에서 이 리포는 git submodule 이지만, 의존성 설치는 소비자가 자동으로 하지 않는다(`pnpm install` 을 한 번 직접 돌린다). 미설치 상태로 부르면 자식 프로세스가 시끄럽게 죽고 소비자가 설치 안내를 띄운다 — 조용히 빈 데이터로 통과하지 않는다.

## 개발

```bash
pnpm test              # vitest
pnpm test:coverage
pnpm format            # prettier --write .
pnpm format:check
```

`vault/` 는 prettier 대상에서 제외한다 — append-only 데이터이고 커밋 해시가 정체성이라 포매터가 손대면 안 된다.

이 리포는 eslint 를 쓰지 않는다. 제품은 데이터고 스크립트는 그 데이터를 읽는 도구라는 성격 때문이다.
