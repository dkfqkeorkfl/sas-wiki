# sas-wiki

마크다운 vault(→ [저장소 구조](#저장소-구조) 에서 정의) 와 **git 히스토리**를 입력으로 받아, 위키 화면과 뉴스 피드에 필요한 JSON 을 CLI 로 뱉는 데이터 리포지토리다.

서버가 아니다. `node scripts/<이름>.mjs` 로 실행하면 endpoint CLI 는 stdout 에 JSON 한 줄을 낸다. 빌드 경로는 `summary --out` 이 summary 아티팩트를, `feeds --out` 이 feeds 아티팩트를, `validate --report` 가 리포트를 쓴다 — [산출물](#산출물). 소비자(개발 서버·미래의 실서버)는 프로세스를 띄워 stdout JSON 을 받아간다.

**검증은 생성의 전제다.** `validate` 가 문서 단위 제외와 검증 게이트를 먼저 통과시킨 뒤에야 빌드 체인이 아티팩트를 발행하고, 세 엔드포인트는 그 아티팩트를 읽는다. 그래서 _서빙되는 데이터 = 검증 통과 데이터_ 가 구조로 보장된다 — [게이트는 어디서 도는가](#게이트는-어디서-도는가).

핵심 아이디어 두 개만 알면 나머지는 따라온다.

1. **문서의 정체성은 경로가 아니라 frontmatter**(문서 맨 위 `---` 로 감싼 YAML 블록)**에 적힌 UUIDv7 `id`** 다. 그래서 문서를 옮기고 이름을 바꾸고 전면 재작성해도 과거 뉴스가 그 문서를 계속 가리킨다.
2. **`feed:` 커밋 하나가 뉴스 카드 하나**다. 뉴스는 별도 파일에 손으로 적는 게 아니라 커밋에서 유도된다. 그래서 피드는 그 자체로 변경 이력이자 감사 추적이 된다.

## 빠른 시작

```bash
pnpm install                 # 최초 1회 (런타임 의존성: unified/remark/rehype)

pnpm run build-dev           # validate → summary 아티팩트 → feeds 아티팩트
pnpm run summary --env dev   # 화면 뼈대(문서 목록·폴더 트리·태그), stdout 전용
pnpm run feeds --env dev --count 20
pnpm run wiki --env dev --path 'company/삼성전자'
pnpm run validate            # vault 무결성 검사 — --env dev 고정, JSON 대신 exit code 로 말한다
```

`--env dev` 는 초안(draft) 문서까지 전부 보고, `--env prod` 는 초안을 뺀다 — 자세한 건 [dev / prod](#dev--prod).

플래그는 `--` 없이 그대로 이어 붙인다. 이 리포의 pnpm(11.x)은 `--` 를 스크립트에 그대로 넘기는데, 세 스크립트(`summary`·`feeds`·`wiki`)는 위치 인자를 받지 않으므로 `pnpm run summary -- --env dev` 는 `Unexpected argument '--env'` 로 죽는다.

스크립트를 직접 불러도 된다. 결과는 같다.

```bash
node scripts/feeds.mjs --env dev --count 20
```

소비자(개발 서버·미래 서버)는 후자 형태로 부른다. `pnpm run <이름>` 은 소비자와 결합돼 있지 않아 바뀌어도 소비자가 알 수 없는 계약이지만, `node <파일>` 은 파일 경로가 곧 계약이라 깨지면 시끄럽게 깨진다.

## 저장소 구조

```text
wiki/**/*.md            문서 원본. 폴더 구조가 곧 위키의 계층이다
scripts/
  summary.mjs           엔드포인트 겸 생성기 — 화면 뼈대 + summary 아티팩트
  feeds.mjs             엔드포인트 겸 생성기 — 뉴스 피드 + feeds 아티팩트
  wiki.mjs              엔드포인트 — 문서 1건 본문
  validate.mjs          무결성 검사 CLI (엔드포인트 아님 — JSON 을 안 낸다)
  lib/                  순수 함수 부품 (파싱·git 워크·렌더·불변식)
  schema/               JSON Schema 6종 — 아래 산출물 참고
cache/                  발행 아티팩트(gitignore)
logs/                   생성 리포트(gitignore)
ignore-feeds.json       잘못 발행한 피드를 억제하는 목록(tombstone). 아래 피드 발행법 참고
```

## 산출물

`build`/`build-dev` 체인이 validate → summary → feeds 순서로 만든다. 경로와 버전은 아래가 정본이다.

<!-- contract:artifacts -->

| 산출물     | 경로                             | 무엇                                    |
| ---------- | -------------------------------- | --------------------------------------- |
| summary    | `cache/summary.<env>.json`       | 화면 뼈대. **유일한 wire 아티팩트**     |
| feeds      | `cache/feeds.<env>.json`         | 최근 200건 윈도우. 응답과 **같은 형태** |
| 리포트     | `logs/summary.report.<env>.json` | 제외 문서·prune 진단. 관측 채널         |
| 리포트(문) | `logs/summary.report.<env>.txt`  | 위와 같은 내용의 사람용                 |

- 봉투는 `schemaVersion: 1` 을 싣는다. summary·feeds 아티팩트와 wire 페이로드가 같은 값을 쓴다.
- **쓰기 순서는 계약이다: validate → summary → feeds.** 도중에 죽으면 뒤 단계 산출물이 갱신되지 않는다.
  신선도 판정은 없고, 호출자는 빌드를 명시적으로 다시 실행해야 한다.
- 생성기는 재생성 건너뛰기를 하지 않는다. 같은 입력을 주면 같은 payload 를 계산하고, 쓰기 여부는 호출자가
  명시한 출력 경로가 결정한다.
- 독자는 발행물을 **전면 불신**한다. 부재·파싱 실패·버전 불일치·env 불일치를 실패로 보고, 옛 계약과 새
  계약을 동시에 지원하지 않는다.

스키마 6종(`scripts/schema/`):

| 파일                       | 무엇                                              |
| -------------------------- | ------------------------------------------------- |
| `wiki-doc.schema.json`     | 문서 frontmatter                                  |
| `summary.schema.json`      | summary wire                                      |
| `feeds.schema.json`        | feeds 페이지 — 응답과 발행 아티팩트가 같은 형태다 |
| `body.schema.json`         | 본문(내부)                                        |
| `report.schema.json`       | 생성 리포트                                       |
| `ignore-feeds.schema.json` | 억제 목록                                         |

<!-- /contract:artifacts -->

용어 두 개를 먼저 못 박는다.

- **vault** — `wiki/` 아래의 마크다운 문서 전체. 이 리포에서 "데이터" 라고 하면 이것이다.
- **엔드포인트** — 소비자가 프로세스로 띄워 JSON 페이로드를 받아가는 세 스크립트(`summary`·`feeds`·`wiki`). `validate` 는 JSON 을 내지 않으므로 엔드포인트가 아니다.

각 엔드포인트 파일은 **순수 함수 export + 얇은 CLI 가드**의 이중 모드다. 함수 export 는 테스트와 리포 내부 재사용을 위한 것이고, **바깥 소비자에게 노출되는 계약은 프로세스 경계(CLI)뿐이다** — 이유는 아래 [누가 이걸 소비하나](#누가-이걸-소비하나) 에 있다. 서빙 로직은 어디에도 없다.

## 데이터 모델

### 문서 — 위키의 단위

문서 하나 = `wiki/` 아래 마크다운 파일 하나. **frontmatter**(문서 맨 위 `---` 로 감싼 YAML 블록)가 메타데이터, 그 아래가 본문이다.

```markdown
---
id: '01088d26-ee68-7a11-b53c-398f328d520e'
title: 삼성전자
type: company
status: active
aliases: ['Samsung', '005930']
tags: ['반도체', '메모리']
meta:
  ticker: '005930'
  sector: '반도체'
  exchange: 'KOSPI'
---

## 개요

삼성전자는 …
```

### 문서 id — 정체성은 경로가 아니다

`id` 는 사람이 직접 적는 **UUIDv7** 이고, 한 번 적으면 절대 바뀌지 않는다. 내용 안에 살기 때문에 이동·이름변경·전면재작성을 모두 견딘다.

id 에는 게이트 세 개가 걸린다.

| 게이트 | 내용                                                                  | 어디서 도는가        |
| ------ | --------------------------------------------------------------------- | -------------------- |
| 형식   | UUIDv7 패턴에 맞아야 한다                                             | `validate` 만        |
| 유일성 | 살아 있는 문서끼리 id 가 겹치면 안 된다 ([불변식](#불변식-7종) 8)     | 엔드포인트 포함 전부 |
| 불변성 | **생성 커밋의 blob 에 적힌 id** 와 현재 frontmatter id 가 같아야 한다 | `validate` 만        |

"`validate` 만" 이라는 오른쪽 칸은 **`validate` 를 직접 실행할 때 걸린다**는 뜻이다. 서빙 쪽에서는 [생성기가 발행 전에](#게이트는-어디서-도는가) 형식·불변성 위반 문서를 아예 제외하므로 그 문서는 응답에 나타나지 않는다.

id 체계 이전에 만들어진 문서는 생성 시점에 id 가 없으므로 불변성 게이트를 통과한다(없는 것과 비교하지 않는다).

**지운 경로에 다시 문서를 만들면 그건 복원이 아니라 새 문서다.** 새 id 를 새로 적어야 한다. 경로는 정체성이 아니고, 삭제는 그 문서를 가리키던 피드를 걷어내기(prune) 때문에, 같은 경로에 옛 id 를 다시 쓰면 걷어냈던 이력이 엉뚱한 새 내용 위로 되살아난다. `validate` 가 이걸 별도 게이트로 막는다.

피드 id 와는 폭으로 구분된다 — 문서 id 는 UUIDv7, 피드 id 는 12자리 hex 라 절대 충돌하지 않는다.

시간을 건너뛰는 참조(피드·태그·트리)는 **id** 로, 지금 이 순간의 스냅샷과 URL 은 **현재 경로**로 가리킨다.

### 계층 — 폴더가 곧 경로다

문서의 위치는 frontmatter 에 적지 않는다. 폴더 구조에서 유도한다.

```text
wiki/company/삼성전자.md
        → breadcrumb = ["company", "삼성전자"]
        → path       = "company/삼성전자"   (breadcrumb.join('/'))
```

**문서**의 계약에는 문자열 `path` 필드가 없다 — summary 의 `docs[]` 를 봐도 `breadcrumb` 뿐이고, 경로는 거기서 만든다. (`tree[]` 는 문서가 아니라 폴더 노드라 `path` 를 직접 갖는다. wiki 응답의 `path` 는 요청에 쓴 ref 를 그대로 돌려주는 에코다.)

### 피드 — 커밋 하나가 뉴스 하나다

`feed:` 로 시작하는 커밋 하나가 뉴스 카드 하나가 된다. 커밋 제목이 헤드라인, 본문이 카드 본문, 그 커밋이 건드린 문서들이 "관련 문서" 칩이 된다.

뉴스를 별도 파일로 관리하지 않는 이유: 그렇게 하면 "무엇이 바뀌었나"(git)와 "무엇이 뉴스인가"(파일)가 따로 놀다가 반드시 어긋난다. 커밋에서 유도하면 둘이 구조적으로 같은 것이 된다.

피드가 문서를 가리킬 때는 **그 커밋 시점의 경로**를 git rename 추적으로 따라가 현재 문서 id 로 해석한다. 그래서 문서를 옮겨도 과거 뉴스가 살아 있다.

## CLI

### 공통 계약

네 스크립트가 모두 지키는 규약이다.

| 항목      | 계약                                                                |
| --------- | ------------------------------------------------------------------- |
| 성공 출력 | **stdout 에 JSON 한 줄** + 개행 (validate 제외)                     |
| 실패 출력 | stderr 에 에러 메시지 + 0 이 아닌 [종료 코드](#종료-코드)           |
| `--vault` | 생략하면 **이 스크립트가 속한 리포 루트**. 현재 디렉토리와 무관하다 |
| `--env`   | `dev` \| `prod`. 생략하면 `prod`                                    |
| 위치 인자 | 받지 않는다. 전부 이름 있는 플래그다                                |

`--vault` 기본값은 cwd 폴백이 아니라 `import.meta.url` 에서 유도한다. 어디서 부르든 자기 리포를 읽으므로 엉뚱한 디렉토리를 파싱하는 사고가 나지 않는다. 다른 vault 를 읽으려면 명시적으로 `--vault <경로>` 를 준다.

`--env` 는 **fail-closed** 다 — **미지정**이면 prod 로 떨어진다. 실수하면 더 많이 보이는 쪽이 아니라 **더 적게 보이는 쪽**으로 잘못된다.

단 **오타는 조용히 폴백하지 않는다.** 열거값(`dev`\|`prod`)이 아닌 값은 네 스크립트 모두 [exit 2](#종료-코드) 로 끊는다. `--env Dev` 하나로 dev 예제를 본다고 믿는 사람이 prod 산출물을 받는 것(반대 방향이면 미공개 데이터 누출)을 막기 위해서다. 여기서 막는 것은 **오타뿐**이고, 미지정은 여전히 prod 다.

### summary

화면 뼈대. 사이드바 트리·태그·검색 색인·필터에 필요한 것만 담고 **본문은 담지 않는다**. 기본 실행은 아무 파일도 쓰지 않고 stdout 에 summary payload 한 줄만 낸다.

```bash
node scripts/summary.mjs [--vault <dir>] [--env dev|prod]
                         [--out <file>] [--max-excluded <n>]
```

| 플래그             | 의미                                                           |
| ------------------ | -------------------------------------------------------------- |
| `--out`            | summary 아티팩트 경로. 상대 경로는 `--vault` 기준으로 해석한다 |
| `--max-excluded n` | 제외 문서가 n건을 넘으면 exit 3. 산출물은 이미 발행된다        |

기본 실행은 캐시 봉투를 만들지 않는다. 산출물 발행은 명시 출력 경로를 받은 빌드 경로가 담당한다.

### feeds

뉴스 피드. 커서 위치에서 `--count` 건을 git 히스토리에서 직접 계산한다 — 억제 반영·커서 페이징까지 여기서 끝난다.

```bash
node scripts/feeds.mjs [--vault <dir>] [--env dev|prod]
                       --count <n> [--after <cursor>]
                       [--ignore <file>] [--out <file>]
```

| 플래그     | 기본값          | 의미                                                                          |
| ---------- | --------------- | ----------------------------------------------------------------------------- |
| `--count`  | **필수**        | 페이지 크기(1 이상 정수). 누락·무효면 [exit 2](#종료-코드) — 조용한 폴백 없음 |
| `--after`  | 없음            | 커서. 반환값의 `nextCursor` 를 **그대로** 넘긴다(12자리 소문자 16진수)        |
| `--ignore` | 없음(억제 없음) | 억제 목록 파일 경로. 상대 경로는 `--vault` 기준                               |
| `--out`    | 없음            | feeds 아티팩트 생성 모드. stdout 은 비고 상대 경로는 vault 기준               |

빌드 체인은 `--count 200 --ignore ignore-feeds.json --out cache/feeds.<env>.json` 을 넘긴다. 200은 그 인자 자체가 소유하는 윈도우 크기이며 별도 상수는 없다.

`--count` 에 기본값이 없는 것은 의도다. 오배선(`abc`·`0`·`-5`·`1.9`)이 조용히 어떤 개수로 흡수되면 그 실패는 관측되지 않는다 — 값이 1 이상의 정수 표기가 아니면 끊는다.

억제도 명시 인자로만 걸린다. 파일이 vault 에 있다는 이유로 자동 적용되지 않으므로, 억제를 원하는 호출자(빌드 체인·서버)가 `--ignore` 를 붙인다.

```bash
# 1페이지 → items: bd8bf74279b0, 4eb6ee1c9d6b
#           nextCursor: "4eb6ee1c9d6b"
node scripts/feeds.mjs --env dev --count 2
# 2페이지 — 1페이지 응답의 nextCursor 를 그대로 넘긴다 → items: 0192a9222428, eca3be1e87bd
node scripts/feeds.mjs --env dev --count 2 --after 4eb6ee1c9d6b
```

커서는 **불투명 문자열**이다. 클라이언트는 파싱·생성·수정·비교하지 않고 받은 값을 그대로 되돌린다 — 값이 마침 item `id` 와 같아도 그 계약은 그대로다.

`nextCursor` 가 `null` 인 것은 **히스토리 끝**을 뜻하며, 그것이 「끝」을 알리는 유일한 신호다. 억제가 밀집한 구간에서 `items` 가 0건이어도 커서는 끊기지 않는다(계속 넘기면 결국 전체를 지나간다).

순서는 **git 워크 순서**다 — 정렬 플래그를 붙이지 않으므로 `git rev-list` 기본 순서가 곧 페이지 순서이고 `nextCursor` 의 근거다.

### wiki

문서 1건. 본문은 여기서만 나온다(지연 로드).

```bash
node scripts/wiki.mjs [--vault <dir>] [--env dev|prod] --path <경로>
```

`--path` 는 `breadcrumb.join('/')` 형태다 — 확장자도, `wiki/` 접두사도 붙이지 않는다.

```bash
node scripts/wiki.mjs --env dev --path 'company/삼성전자'
```

### validate

vault 무결성 검사와 리포트 출력의 소유자. 페이로드를 메모리에서 조립해 게이트를 전량 돌리고, 통과하면 exit 0, 위반하면 사유를 출력하고 exit 1 로 죽는다.

```bash
node scripts/validate.mjs [--vault <dir>] [--env dev|prod] [--schema <dir>]
                          [--deadlinks ignore|warn|error] [--max-excluded <n>]
                          [--report <dir>]
```

| 플래그           | 의미                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| `--env`          | 미지정 시 prod + **stderr 경고**. 알 수 없는 값은 에러로 끊는다       |
| `--schema`       | 스키마 디렉토리 override (기본 `scripts/schema`)                      |
| `--deadlinks`    | 데드링크 심각도. `ignore`, `warn`(기본), `error` 중 하나              |
| `--max-excluded` | 문서 단위 제외 허용치. 기본 0. 초과 시 validate 는 exit 1             |
| `--report`       | 리포트 디렉토리. 미지정 시 쓰지 않는다; 상대 경로는 `--vault` 기준    |
| `--help` `-h`    | 사용법 출력                                                           |
| `--out` `--root` | **제거됨**. 넘기면 에러로 끊는다 (JSON 을 안 만드니 출력 인자도 없다) |

> `pnpm run validate` 는 **`--env dev` 가 박혀 있다.** prod 를 검증하려면 `node scripts/validate.mjs` 를 직접 부른다. 둘은 결과가 크게 다르다 — 이 리포의 예제 vault 는 전량 draft 라 prod 에서는 `docs=0` 이 나온다.

돌리는 게이트: 커밋 컨벤션 → 문서 단위 제외(`NO_FRONTMATTER`, `MISSING_TYPE`, `SCHEMA_VIOLATION`, `DUPLICATE_PATH`, `DUPLICATE_ID`, `ID_TAMPERED`, `DELETED_ID_REUSE`) → 데드링크 → 피드 해석 실패 → 산출물 스키마(strict) → [불변식 7종](#불변식-7종).

출력은 JSON 이 아니라 요약 한 줄이다. `--report` 를 명시하면 리포트는 게이트보다 먼저 기록되므로, 피드 해석 실패처럼 검증이 막히는 상황에서도 진단 JSON/TXT 가 남는다. 리포트 쓰기 실패는 검증 판정을 실패로 승격하지 않고 stderr 로만 알린다. 기본 실행은 리포트를 쓰지 않아 vault 를 더럽히지 않는다.

```text
[wiki] docs=6 body=5 feeds=5 prune=1 prunedFeeds=1 unresolved=0 warnings=0
```

경고가 있으면 그 아래로 항목별 줄이 더 붙는다. 라벨은 4종이다.

`build`/`build-dev` 의 feeds 단계는 `--count 200` 으로 feeds 아티팩트를 최근 200건까지 줄인다. validate 의 게이트 5(산출물 스키마), 6(불변식), 7(억제 목록 위생)은 `parseVault` 가 조립한 전체 vault와 validate 내부 wire 를 대상으로 돈다. 그래서 캐시 윈도우가 200건이어도 게이트 전제는 바뀌지 않는다.

<!-- contract:warning-labels -->

```text
[wiki]   deadlink: <출처> -> [[대상]] (사유)
[wiki]   unpublished-feed: <sha12> "<제목>"
[wiki]   unresolved: <sha12> <경로>
[wiki]   warning: <sha12> <사유>
```

<!-- /contract:warning-labels -->

**출력을 한 줄로 가정하고 파싱하지 마라.** `warnings` 는 실패가 아니다 — exit code 에 영향을 주지 않는다.

`prune` = 삭제·draft 배제로 걷어낸 피드 참조 수, `prunedFeeds` = 참조가 전부 걷혀 통째로 사라진 피드 수. 이 숫자가 갑자기 튀면 rename 추적이 깨졌다는 신호이므로 0 이어도 항상 찍는다. (위 숫자는 이 리포 예제 vault 의 `--env dev` 실측값이라 vault 상태에 따라 달라진다.)

### 게이트는 어디서 도는가

**검증은 생성의 전제다.** 생성기(`summary`)가 전체 파싱 중 문서를 **한 건씩** 심사해 불량 문서를 제외한 뒤에야 아티팩트를 발행한다. 세 엔드포인트는 그 아티팩트를 읽으므로 _서빙되는 데이터 = 검증 통과 데이터_ 가 구조로 보장된다. 엔드포인트가 vault 를 자체 재파싱하던 시절에는 이것이 성립하지 않았고, 그때는 id 를 사후 변조한 커밋의 문서가 그대로 서빙됐다.

제외 사유는 7종이고, **제외는 `docs` 와 `tree` 양쪽에 전파된다**(트리에 유령 노드가 남지 않는다).

<!-- contract:reason-codes -->

| 사유 코드          | 언제                                            |
| ------------------ | ----------------------------------------------- |
| `NO_FRONTMATTER`   | frontmatter 블록이 없다                         |
| `MISSING_TYPE`     | `type` 이 없다                                  |
| `SCHEMA_VIOLATION` | frontmatter 가 스키마를 어긴다                  |
| `DUPLICATE_PATH`   | 같은 경로가 둘이다                              |
| `DUPLICATE_ID`     | 살아 있는 문서끼리 id 가 겹친다(**둘 다** 제외) |
| `ID_TAMPERED`      | 생성 커밋의 id 와 지금 id 가 다르다             |
| `DELETED_ID_REUSE` | 삭제된 문서의 id 를 다시 썼다                   |

<!-- /contract:reason-codes -->

제외된 문서는 **리포트에 사유와 함께 남고** stderr 에도 요약이 나간다 — 조용히 사라지지 않는다.

**여전히 자동으로 도는 것은 없다.** 이 리포에는 pre-commit 훅도 CI 도 없다. 생성기와 `validate` 는 누군가 직접 실행해야 돈다. 다만 **엔드포인트가 무검증 데이터를 내보내는 경로는 이제 없다** — 필요한 아티팩트가 없거나 남은 봉투 검증을 통과하지 못하면 다시 만들지 않고, 옛 세대를 200 으로 흘리지 않은 채 시끄럽게 죽는다.

### 종료 코드

<!-- contract:exit-codes -->

| 코드     | 뜻                                                                     |
| -------- | ---------------------------------------------------------------------- |
| `exit 0` | 산출물 생성 성공(`clean` 또는 `partial` — 제외가 있어도 발행은 된다)   |
| `exit 1` | 전역 실패(git 고장·shallow clone·쓰기 실패·스크립트 버그)              |
| `exit 2` | 사용법 위반(알 수 없는 `--env` 값 등)                                  |
| `exit 3` | `--max-excluded` 초과. **생성기 전용** opt-in — 산출물은 이미 발행됐다 |

<!-- /contract:exit-codes -->

`--env` 오타는 조용히 prod 로 떨어지지 않고 **exit 2** 다. 미지정만 prod 다.

다만 엔드포인트도 무조건 살아 나오지는 않는다. 파싱 자체가 불가능한 상태에서는 exit 1 로 죽는다. 대표적으로는:

| 엔드포인트도 죽는 조건                  | 어디에 설명이 있나                                                                |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| 문서 id 중복                            | [불변식](#불변식-7종) 8 — 유일성만 전 경로 검사                                   |
| 생성 커밋 없음(미커밋 문서)             | [저장만으로는 아무 일도 일어나지 않는다](#저장만으로는-아무-일도-일어나지-않는다) |
| shallow·partial clone, git 자체가 없음  | [클론 요건](#클론-요건)                                                           |
| `ignore-feeds.json` 파싱·스키마 위반    | [잘못 발행한 피드 되돌리기](#잘못-발행한-피드-되돌리기)                           |
| frontmatter 구조가 깨짐(`type` 부재 등) | —                                                                                 |
| 한 문서 안에 중복 블록 id               | —                                                                                 |
| `--after` 커서에 `ts`·`feedId` 가 빠짐  | [feeds](#feeds)                                                                   |

**주의 — 방향이 직관과 반대인 경우가 있다.** frontmatter 가 _깨진_ 문서는 엔드포인트를 죽이지만, frontmatter 가 **아예 없는** 파일은 조용히 건너뛴다. 그 문서만 소리 없이 사라지고 나머지는 정상 응답한다. 이런 "떠돌이 파일" 은 `validate` 만 잡는다.

`validate` 에서만 걸리는 것: 커밋 가드(추가+삭제 동시)·데드링크·피드 해석 실패·떠돌이 파일·응답 스키마 strict·[불변식](#불변식-7종) 전량. 문서 단위 제외 사유 7종은 **생성기도 같은 판정을 한다** — 차이는 `validate` 가 그것을 실패로 올린다는 것뿐이다.

> 문서를 고치거나 피드를 발행한 뒤에는 커밋을 밀기 전에 `pnpm run validate` 를 돌린다. 이게 이 리포의 유일한 안전망이다.

## 반환 데이터형

세 엔드포인트의 반환값을 하나씩 본다. 예시는 이 리포의 예제 vault 를 `--env dev` 로 돌린 **실제 출력**이며, 길면 `…` 로 줄였다. (한 곳만 예외 — wiki 의 `sources` 는 예제 vault 에 각주가 하나도 없어 실제로는 `[]` 라, 거기만 형상 예시다.)

summary 와 feeds 는 같은 `sourceCommit`(= 그 응답을 만든 커밋의 40자 해시, **세대 식별자**)을 가질 때만 한 세트다. 세대가 섞이면 참조가 조용히 깨지므로 소비자는 반드시 같은 세대끼리 묶어 쓴다. wiki 응답에는 `sourceCommit` 이 없으므로 세대 대조는 summary·feeds 로 한다.

### summary 반환값

<!-- contract:summary-payload -->

```jsonc
{
  "schemaVersion": 1,
  "env": "dev",
  "generatedAt": "2026-07-26T03:35:20.000Z",
  "sourceCommit": "5a624e1b9c2d0f3e8a71c4b5d6e2f9a0c8b3d417",
  "docs": [/* … */],
  "tree": [/* … */],
  "tags": {/* … */},
}
```

| 키              | 타입                 | 설명                                                                                                                 |
| --------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | `number`             | **내부 wire 계약 버전** — 릴리즈 버전이 아니다. 아래 「계약 버전의 의미」 참조                                       |
| `env`           | `string`             | `dev` \| `prod`. 경로와 **독립으로** 대조하기 위해 파일 안에도 싣는다                                                |
| `generatedAt`   | `string`             | **실행 시각이 아니다.** 가장 최근 문서 `updated`/피드 `ts` 에서 유도한 결정적 값(`SOURCE_DATE_EPOCH` 가 있으면 그것) |
| `sourceCommit`  | `string`             | 이 응답을 만든 커밋의 40자 해시. **세대 식별자**                                                                     |
| `docs`          | `SummaryDoc[]`       | 문서 목록. status 로 모양이 갈린다                                                                                   |
| `tree`          | `TreeNode[]`         | 폴더 트리 (재귀)                                                                                                     |
| `tags`          | `Record<태그, id[]>` | 태그 → 문서 id 역색인. active 문서만                                                                                 |

#### 계약 버전의 의미

`schemaVersion` 은 **이 리포 안에서만 쓰는 wire 계약 번호**다. 패키지 릴리즈 버전이 아니고, semver 도 아니다.

- **읽는 법은 등가 비교 하나뿐이다.** 소비자는 `===` 로 같은지만 본다 — 크다/작다를 따지는 코드는 어디에도 없고, "이 버전 이상이면 호환" 같은 규칙도 없다. 값이 다르면 **해석하지 않고 통째로 실패로 접는다**(옛 계약과 새 계약을 동시에 지원하지 않는다).
- **그래서 minor/patch 로 쪼개지 않는다.** 응답은 strict 로 검증하므로(`additionalProperties: false`) 필드를 **하나 추가하는 것도 소비자에겐 파괴적**이다. "안전한 추가" 라는 등급이 성립하지 않으니 나눌 축이 없다.
- **지금 값은 1이다.** 내부 R&D 단계의 계약 재구성이고, gitlink 배포는 업데이트를 강제할 수 있으므로 이전 내부 번호를 이어받지 않는다.
- 캐시 신선도 판정은 없다. 번호는 **계약 모양이 바뀌었음을 사람이 명시하는 표지**다.

**`docs[]` — status 로 갈리는 유니온.**

active 문서는 10키다.

```jsonc
{
  "id": "01088d26-ee68-7a11-b53c-398f328d520e",
  "breadcrumb": ["company", "삼성전자"],
  "title": "삼성전자",
  "status": "active",
  "type": "company", // concept | company | moc
  "tags": ["반도체", "메모리"],
  "aliases": ["Samsung", "005930"], // 검색용 별칭
  "excerpt": "삼성전자는 메모리·시스템 반도체와 …", // 본문 첫 문단 요약
  "created": "2006-01-02T22:05:05Z", // git 이 아는 생성 커밋 시각
  "updated": "2026-07-23T14:11:49+09:00", // 마지막 수정 커밋 시각
}
```

`status: "disable"` 문서는 **4키 스텁**만 남는다. 본문은 지우되 링크는 살려두기 위해서다 — 과거 피드나 위키링크가 이 문서를 가리키고 있어도 제목만은 보여줄 수 있다.

```jsonc
{
  "id": "01088d2a-97e8-7dcd-808d-3b7f9180fa79",
  "breadcrumb": ["concept", "온디바이스-AI"],
  "title": "온디바이스 AI",
  "status": "disable",
}
```

`created`/`updated` 는 frontmatter 에 적는 게 아니라 git 히스토리에서 유도한다. 적으면 검증이 거부한다.

**`tree[]` — 폴더 노드.**

```jsonc
[
  { "path": "company", "docs": ["01088d27-…", "01088d28-…", "01088d26-…"], "children": [] },
  { "path": "moc", "docs": ["01088d2c-…"], "children": [] },
  { "path": "tech", "docs": ["01088d29-…"], "children": [] },
]
```

`docs` 에는 **active 문서 id 만** 들어간다. 그래서 disable 문서만 있는 폴더는 노드 자체가 없다(이 리포의 예제 vault 에서 `concept` 이 트리에 없는 이유다). `path` 는 항상 그 문서들의 `breadcrumb.slice(0, -1).join('/')` 와 일치한다.

**`tags`**

```jsonc
{
  "메모리": ["01088d27-…", "01088d26-…", "01088d29-…"],
  "반도체": ["01088d27-…", "01088d28-…", "01088d26-…", "01088d2c-…"],
  "파운드리": ["01088d28-…"],
  "AI": ["01088d29-…"],
}
```

태그의 정본은 문서 frontmatter 다. 피드에는 태그가 없다(피드는 `keywords` 를 따로 갖는다).

<!-- /contract:summary-payload -->

### feeds 반환값

<!-- contract:feeds-payload -->

```jsonc
{
  "schemaVersion": 1,
  "env": "dev",
  "generatedAt": "2026-07-26T03:35:20.000Z",
  "sourceCommit": "5a624e1b…",
  "items": [/* … */],
  "nextCursor": null,
}
```

**`items[]` — 정확히 7키.**

```jsonc
{
  "id": "fdabfe65a127", // 커밋 해시 앞 12자리
  "ts": "2006-01-02T22:12:05Z", // author date
  "title": "삼성전자, HBM3E 12단 양산 승인", // 커밋 제목의 "feed: " 뒤
  "body": "삼성전자가 HBM3E 12단 제품의 양산 승인을 획득했다. 하반기 공급이 시작된다.", // 커밋 본문(트레일러 줄 제외 — 아래 피드 발행법)
  "keywords": ["HBM", "양산", "삼성전자"], // Keywords: 트레일러
  "importance": "breaking", // normal | highlight | breaking | fix
  "docs": [{ "id": "01088d26-ee68-7a11-b53c-398f328d520e" }],
}
```

**`docs[]` — 이 커밋이 고친 문서. 정확히 1키.**

| 키   | 타입     | 설명                                                   |
| ---- | -------- | ------------------------------------------------------ |
| `id` | `string` | 문서 id. **경로가 아니다** — 문서가 이동해도 안 깨진다 |

> **피드는 문서를 가리킬 뿐, 문서 안의 위치는 가리키지 않는다.** 카드의 점프는 문서 단위다 — 문서 안쪽으로 들어가는 링크는 [위키링크](#위키링크) 가 담당한다.

**`nextCursor` — 커서 페이징.** 12자리 소문자 16진수 문자열이다.

```jsonc
"eca3be1e87bd"
```

**`null` 은 히스토리 끝을 뜻하며, 그것이 「끝」을 알리는 유일한 신호다.** 억제가 밀집한 구간에서 `items` 가 0건이어도 값은 남는다 — 0건에 `null` 을 주면 「끝」을 거짓으로 신고하는 것이고, 그 순간 "계속 넘기면 결국 전체를 지나간다"는 보장이 깨진다.

값은 **이번 페이지 마지막 항목**의 재개 지점이며(0건이면 마지막으로 워크한 커밋), 그대로 다음 호출의 `--after` 에 넣으면 된다. 오프셋이 아니라 커밋 좌표라서 그 사이에 피드가 늘어도 밀리거나 중복되지 않는다.

값이 마침 item `id` 와 같지만 **커서는 불투명 문자열**이다 — 파싱·생성·수정·비교하지 않고 받은 값을 그대로 되돌린다. 그래야 나중에 데이터 소스가 git 이 아니게 되어도 계약이 살아남는다.

**`env` — `dev` | `prod`.** 응답에도 아티팩트에도 실린다. `schemaVersion` 이 동결돼 표지 대조의 구분력이 사라졌으므로, 엉뚱한 환경의 산출물이 서빙되는 것을 막는 판별축은 이것 하나다.

### wiki 반환값

<!-- contract:wiki-payload -->

`--path` 가 무엇을 가리키느냐에 따라 셋 중 하나다.

**① active 문서 — 7키.**

```jsonc
{
  "path": "company/삼성전자",
  "breadcrumb": ["company", "삼성전자"],
  "status": "active",
  "html": "<h2 id=\"개요\">개요</h2>\n<p>…</p>",
  "headings": [
    { "anchor": "개요", "level": 2, "text": "개요" },

    { "anchor": "메모리-로드맵", "level": 2, "text": "메모리 로드맵" },
  ],
  "meta": { "ticker": "005930", "sector": "반도체", "exchange": "KOSPI" },
  "sources": [{ "label": "…", "text": "…" }],
}
```

| 키         | 설명                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| `html`     | 렌더 완료된 본문. 위키링크는 `<a class="wiki-link" data-path="…">` 로 나온다 |
| `headings` | 목차·앵커 검증용. `anchor` 는 URL 슬러그, `text` 는 표시용 원문              |
| `meta`     | frontmatter 의 자유 필드 — 인포박스에 그대로 쓰인다                          |
| `sources`  | 본문의 **각주 정의**(`[^라벨]: 내용`)를 모은 것. 없으면 `[]`                 |

마크다운 원문(`md`)·백링크는 계약에 없다. 소비처가 없어서 뺐다.

**주의**: 이 응답에는 `id` 가 없다. 문서 id 가 필요하면 summary 의 `docs[]` 에서 `breadcrumb` 으로 찾는다.

**② disable 문서 — summary 스텁 4키 그대로.** `id`·`breadcrumb`·`title`·`status`.

**③ 없는 경로 — `null`.** 에러가 아니라 `null` 이 stdout 에 찍히고 exit 0 이다.

## 문서 작성법

`wiki/<폴더>/<문서명>.md` 를 만들고 frontmatter 를 채운다.

| 필드      | 필수 | 값                                                        |
| --------- | ---- | --------------------------------------------------------- |
| `id`      | ✔    | UUIDv7. 직접 생성해 적고 **이후 절대 변경 금지**          |
| `title`   | ✔    | 표시 제목                                                 |
| `type`    | ✔    | `concept` \| `company` \| `moc`                           |
| `status`  | ✔    | `active` \| `disable`                                     |
| `aliases` |      | 검색용 별칭 배열 (영문명·티커 등)                         |
| `tags`    |      | 태그 배열                                                 |
| `meta`    |      | 자유 객체 → 인포박스                                      |
| `draft`   |      | dev 전용 표식(불리언). 아래 [dev / prod](#dev--prod) 참고 |

`type: company` 는 `meta.ticker`·`meta.sector`·`meta.exchange` 가 **필수**다(값이 `null` 인 건 허용).

id 는 이렇게 만든다. `uuid` 는 이 리포의 devDependency 라 **리포 루트에서 `pnpm install` 을 한 뒤** 리포 안에서 실행해야 한다.

```bash
node -e "console.log(require('uuid').v7())"
```

`created`·`updated` 는 **적지 않는다.** git 히스토리에서 유도하며, 적혀 있으면 검증이 거부한다.

> **예제 브랜치(`test`)에 문서를 추가한다면 `draft: true` 를 반드시 함께 적는다.** 예제 vault 의 문서는 전부 draft 이고, 새 문서만 draft 없이 들어가면 그 문서만 prod 에 남는다. 그 상태에서 예제 문서로 위키링크를 걸면 prod 검증이 "대상 문서 없음" 데드링크로 죽는다 — 파일은 멀쩡히 있는데 없다고 나오므로 원인을 찾기 매우 어렵다.

### 저장만으로는 아무 일도 일어나지 않는다

새 `.md` 를 만들고 저장한 직후에 CLI 를 돌리면 **세 엔드포인트가 전부 exit 1 로 죽는다.**

```text
생성 커밋을 찾을 수 없습니다: wiki/tech/CXL.md
```

frontmatter 를 틀린 게 아니다. `created` 를 git 에서 유도하는데 생성 커밋이 아직 없어서다. **커밋해야 문서가 존재하기 시작한다.**

```bash
git add wiki/tech/CXL.md
git commit -m "chore: CXL 문서 추가"
```

**생성 커밋에 틀린 id 를 적었다면** amend 하지 마라(히스토리 재작성 금지). 불변성 게이트가 생성 커밋의 blob 과 대조하므로 그 문서는 영구히 `validate` 실패 상태가 된다. 복구는 **삭제 커밋 → 새 id 로 다시 생성 커밋** 이다. 옛 id 는 재사용하지 않는다.

### 각주 = 출처

본문에 마크다운 각주 정의를 쓰면 wiki 응답의 `sources[]` 가 된다. frontmatter 가 아니라 본문이다.

```markdown
자세한 규격은 공개 문서에 있다[^spec].

[^spec]: CXL Consortium, CXL 3.1 Specification (2023)
```

각주 정의 줄은 `sources[]` 로 **복사될 뿐 `html` 에서 제거되지 않는다.** 마커(`[^spec]`)와 정의 줄이 렌더된 본문에 그대로 남으므로, 정의는 본문 맨 아래에 모아 두고 표시는 소비자 쪽에서 처리하는 것을 전제로 한다.

### 위키링크

문서끼리는 `[[대상]]` / `[[대상#앵커]]` 로 잇는다.

- **대상** = 전체 경로(`company/삼성전자`) 또는 **문서 파일명**(`삼성전자`). 파일명이 유일하지 않으면 "동명 문서 충돌" 로 잡힌다.
- **`aliases` 는 링크 대상이 아니다.** `[[Samsung]]` 은 데드링크다 — aliases 는 검색용이다.
- **앵커는 URL 슬러그로 적는다**(`[[삼성전자#메모리-로드맵]]`). heading 원문 그대로(`#메모리 로드맵`) 써도 `validate` 는 통과하지만 슬러그로 정규화되지 않아 실제 점프가 깨진다.

대상이나 앵커가 없으면 `validate` 가 데드링크로 잡는다.

> **앵커가 나오는 자리는 둘뿐이고, 둘 다 문서 안쪽을 가리킨다.**
>
> | 어디                                     | 무엇                                                     | 만드는 곳                    |
> | ---------------------------------------- | -------------------------------------------------------- | ---------------------------- |
> | [wiki 반환값](#wiki-반환값) `headings[]` | 문서 heading 의 URL 슬러그 — 목차 항목이 가리키는 목적지 | `slugifyHeading` (md → html) |
> | 위키링크 `[[대상#앵커]]`                 | 다른 문서의 특정 heading 으로 가는 링크                  | 같은 슬러그 함수 (lockstep)  |
>
> 렌더된 본문의 `<h2 id="…">` 와 `headings[].anchor` 는 **같은 함수로 만들어져** 항상 일치한다. 반면 **피드**(`feeds` 의 `docs[]`)는 문서만 가리키고 위치는 가리키지 않는다 — 거기엔 앵커가 없다.

## 피드 발행법

### 커밋 컨벤션

**기계가 읽는 접두사는 `feed:` 하나뿐이다.** `feed:` 로 시작하는 커밋이 뉴스 카드를 만들고, 나머지 커밋(`chore:`·`docs:`·접두사 없음 등)은 **조용한 저작**이다. 무엇을 쓰든 자유이고 파이프라인은 그것을 보지 않는다.

**저작과 발행이 분리된다.** 아직 뉴스로 내고 싶지 않으면 비-`feed:` 커밋으로 저장해 두었다가, 나중에 `feed:` 커밋으로 발행한다. `feed:` 커밋이 새 문서를 만들어도 된다 — 생성과 발행을 한 커밋에 담는 것을 막지 않는다.

**유일한 커밋 가드**: 한 커밋이 vault 문서 **추가와 삭제를 동시에** 담으면 접두사와 무관하게 `validate` 가 실패한다(exit 1). 이동+전면재작성을 한 커밋에 몰아넣으면 git 이 rename 을 놓치고 **문서 id 가 바뀌어 과거 피드가 전부 끊기기** 때문이다. 이동·이름변경은 `git mv` 로 커밋하면 rename 으로 기록되어 이 가드에 걸리지 않는다.

### feed 커밋 메시지 → 피드 필드

```text
feed: 삼성전자 HBM3E 양산 승인

삼성전자가 HBM3E 12단 제품의 양산 승인을 획득했다. 하반기 공급이 시작된다.

Keywords: HBM, 양산
Importance: breaking
```

| 커밋의 무엇               | 피드의 무엇  |
| ------------------------- | ------------ |
| 커밋 해시 앞 12자리       | `id`         |
| author date               | `ts`         |
| `feed: ` 뒤 제목          | `title`      |
| 본문(트레일러 제외)       | `body`       |
| `Keywords:` 트레일러      | `keywords[]` |
| `Importance:` 트레일러    | `importance` |
| diff 가 건드린 vault 문서 | `docs[].id`  |

### 트레일러 규칙

트레일러 인식 규칙이 조금 까다로우니 정확히 알아두는 게 좋다.

- 커밋 본문의 **마지막 빈 줄 이후 블록 전체**가 후보다.
- 그 블록의 **모든 줄**이 `Key: value` 형태여야 트레일러로 인정된다. 한 줄이라도 아니면 **트레일러 0개**로 처리되고, 그 줄들은 그냥 본문(`body`)에 남는다.
- 키는 대소문자를 구분하지 않는다(`keywords:` 도 된다).
- `Keywords` 는 콤마로 나눈다. 공백은 다듬고 빈 항목은 버린다.
- `importance` 허용값은 아래 4종이다(대소문자 무관). 다른 값을 쓰면 `normal` 로 떨어지고 **경고로 집계**된다 — 조용히 무시하지 않는다. 트레일러가 아예 없으면 `normal`.

<!-- contract:importance -->

| 값          | 뜻                       |
| ----------- | ------------------------ |
| `normal`    | 기본                     |
| `highlight` | 강조                     |
| `breaking`  | 속보                     |
| `fix`       | 기사 없는 단순 정정 알림 |

<!-- /contract:importance -->

`fix` 는 기사가 아니라 정정이므로 **연결된 문서가 0건이면 피드 자체가 사라진다** — 아래 생존 규칙 참고.

즉 트레일러 블록 앞에는 **반드시 빈 줄**이 있어야 하고, 그 블록에 산문을 섞으면 안 된다.

### 피드 생존 규칙

피드가 가리킨 문서가 사라져도 **피드 자체는 대개 살아남는다** — 피드는 문서의 부속물이 아니라 그 자체로 기사이자 감사 추적이기 때문이다. 다만 **참조가 사라진 사유**에 따라 극성이 갈린다.

<!-- contract:feed-ref-reasons -->

| 사유               | 무슨 상황                          | 그 참조  | 피드                             |
| ------------------ | ---------------------------------- | -------- | -------------------------------- |
| `deleted`          | 문서가 삭제됐다                    | 걷어낸다 | **생존**(env 무관)               |
| `draft-excluded`   | prod 에서 draft 라 빠졌다          | 걷어낸다 | prod 미노출(fail-closed 가 우선) |
| `invalid-excluded` | 생성기가 검증으로 제외했다         | 걷어낸다 | **생존**(fail-open)              |
| `unresolved`       | 경로를 현재 문서로 해석하지 못했다 | 걷어낸다 | **드랍**(데이터 결함이다)        |

<!-- /contract:feed-ref-reasons -->

- 참조가 **0건이어도 생존**한다(기사 전용 피드 — 의도된 동작).
- **예외는 `fix` 다** — 정정 알림인데 가리킬 문서가 없으면 무의미하므로 드랍한다.
- 이 판정은 **생성기 안에만** 산다. 서빙은 그 결과를 읽을 뿐 사유를 다시 계산하지 않는다.

### 예제 데이터 규칙

이 리포의 예제 `feed:` 커밋은 진짜 뉴스와 **기계적으로 구분되지 않는다** — 둘 다 그냥 `feed:` 커밋이다. 그래서 예제가 prod 로 새지 않게 하는 것은 규약의 몫이다.

> **예제 `feed:` 커밋은 draft 문서를 최소 1건 건드리고, 그 문서를 삭제하지 않는다.**

두 조건이 **둘 다** 필요하다. 생존 규칙(위)이 사유별로 갈리기 때문이다.

- 문서를 **하나도 안 건드리면** 참조 0건 → 기사 전용 피드로 **생존**한다(env 무관).
- 가리킨 문서를 나중에 **삭제하면** 사유가 `deleted` 가 되어 그것도 **생존**한다(env 무관).

draft 문서를 가리킨 채로 두어야만 prod 에서 `draft-excluded` 로 걸러진다.

> 현 예제 vault 에 이 규칙을 어긴 피드가 **1건 있다** — `폐기예정 메모 관련 소식`. 가리킨 문서가 나중에 삭제돼 사유가 `deleted` 이고, 그래서 `--env prod` 피드에 남는다. 히스토리 재작성이 금지된 이상 커밋으로는 못 고치고, 숨기려면 tombstone 한 줄이면 된다. **데이터 결정이지 코드 결함이 아니다.**

### 잘못 발행한 피드 되돌리기

**히스토리를 다시 쓰지 않는다.** rebase·squash·amend·force-push 는 이 리포에서 금지다 — 커밋 해시가 곧 피드의 정체성이라 히스토리를 손대면 과거 피드가 통째로 뒤틀린다.

대신 `ignore-feeds.json` 에 묘비(tombstone)를 추가해 **억제**한다. 억제는 삭제가 아니다 — 원본 커밋과 문서는 그대로 남고 피드 출력에서만 빠진다. 커밋 없이 파일 저장만으로 즉시 반영된다.

`ignore-feeds.json` 은 **주석을 허용하지 않는 표준 JSON** 이다. 주석을 넣으면 세 엔드포인트가 전부 파싱 에러로 죽는다.

```json
[
  {
    "id": "fdabfe65a127",
    "when": "2026-07-25T14:30:00Z",
    "reason": "수치 오기 — 정정 피드로 대체",
    "by": "shlee"
  }
]
```

| 필드     | 필수 | 값                                                             |
| -------- | ---- | -------------------------------------------------------------- |
| `id`     | ✔    | 억제할 피드 id (= 커밋 해시 앞 12hex)                          |
| `when`   | ✔    | 억제 시각. RFC3339 date-time — `2026-07-25` 처럼 날짜만은 거부 |
| `reason` |      | 억제 사유. 선택이지만 강력 권장 (감사 추적)                    |
| `by`     |      | 억제한 사람                                                    |

## dev / prod

`--env` 는 **draft 문서를 보여줄지**를 결정한다. `dev` 는 전부, `prod` 는 draft 를 뺀다.

문서가 draft 인 판정은 **OR** 다 — 신호가 하나라도 있으면 숨긴다.

| 신호        | 조건                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| frontmatter | `draft` 가 있고 값이 `false` 가 아니면 draft. 즉 `draft: yes` 같은 오타도 숨긴다 |
| 경로        | 문서 경로가 `dev` 이거나 `dev/` 아래면 draft (`develop/` 는 해당 없음)           |

`draft` 에는 `true`/`false` 만 쓴다. 불리언이 아닌 값은 엔드포인트가 숨겨 주긴 하지만(누출은 없다), `validate --env dev` 가 스키마 위반으로 죽인다(`draft` 는 boolean 타입). **prod 검증으로는 이 오타를 못 잡는다** — prod 는 draft 문서를 스키마 검사 _전에_ 빼버리기 때문이다.

두 신호를 AND 가 아니라 OR 로 묶은 이유는 방향 때문이다. 플래그를 깜빡해도 폴더가 잡고, 폴더를 안 써도 플래그가 잡는다. 오타로 **숨는** 사고는 눈에 띄어 금방 고쳐지지만, 오타로 **새는** 사고는 되돌릴 수 없다.

draft 문서는 검증·파생·데드링크 검사보다 **먼저** 제거된다. 그래서 어떤 페이로드에도 흔적이 남지 않는다. draft 문서를 가리키던 피드는 삭제와 같은 방식으로 걷어내고(부재의 사유가 설명되므로 "해석 실패" 로 세지 않는다), 한 피드가 draft 문서와 공개 문서를 함께 가리키면 공개 쪽만 남는다.

dev → prod 승격은 어떤 신호로 숨겼느냐에 따라 다르다.

- **플래그로 숨긴 문서** — `draft` 를 지우면 끝이다. id 도 경로도 바뀌지 않는다.
- **`dev/` 폴더로 숨긴 문서** — 폴더 밖으로 옮겨야 한다. id 는 그대로지만 **경로가 바뀐다**(= URL 과 wiki `--path` 가 바뀐다). 이동은 `git mv` 로 커밋한다(rename 으로 기록돼야 id 가 산다).

## 규칙과 불변식

### 클론 요건

입력은 `wiki/**/*.md` **와 전체 git 히스토리** 둘 다다.

| 입력              | 쓰임                                                         |
| ----------------- | ------------------------------------------------------------ |
| 마크다운 파일     | 현재 내용과 frontmatter (저작된 UUIDv7 `id` 포함)            |
| 전체 git 히스토리 | 생성·수정 시각, 피드, rename 추적, 삭제 반영, id 불변성 검사 |

**shallow clone 과 partial clone 은 유효한 입력이 아니다.** shallow 는 생성 커밋을 가려 날짜와 피드를 조용히 바꾸고, partial 은 검증에 필요한 blob(불변성 게이트가 읽는 생성 시점 frontmatter)을 가린다. 검출되면 응답을 내기 전에 실패한다.

### 불변식 7종

`validate` 가 강제한다. 위반하면 exit 1 로 죽는다.

아래 표의 `summary`·`feeds` 는 같은 이름의 엔드포인트 응답이고, **`body` 는 `validate` 가 메모리에서만 조립하는 내부 페이로드**다(키 = active 문서의 현재 경로, 값 = 그 문서의 본문 4키). wiki 엔드포인트가 문서 1건씩 잘라 주는 것이 이 `body` 의 한 조각이다.

> **6번이 없는 것은 오타가 아니다.** 앵커 정합 불변식이었고 P2 가 앵커 기능과 함께 제거했다.
> **번호는 재사용하지 않는다** — 과거 진단 로그와 교차 참조되는 식별자이지 순번이 아니다.

<!-- contract:invariants -->

| #   | 불변식                                                                                | 깨지면 생기는 일                     |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------ |
| 1   | 모든 `feeds.items[].docs[].id` 가 `summary.docs[].id` 에 존재한다 (disable 스텁 포함) | 피드 카드가 제목·태그·점프를 잃는다  |
| 2   | `body.docs` 의 키 집합 = active 문서의 현재 경로 집합                                 | 문서를 눌러도 본문이 없다            |
| 3   | `tree[].docs[]` 는 active id 만 담고, 모든 active 문서는 정확히 한 노드에 속한다      | 사이드바 행이 비거나 사라진다        |
| 4   | `tags[*]` 는 active id 만 담는다                                                      | 태그 페이지가 비거나 개수가 오염된다 |
| 5   | `tree[].path` = 그 문서들의 `breadcrumb.slice(0, -1).join('/')`                       | 서브트리 필터가 엉뚱한 문서를 낸다   |
| 7   | 세 페이로드(summary·feeds·body)의 `sourceCommit` 이 같고, 한 세트로만 소비된다        | 세대가 섞여 참조가 조용히 깨진다     |
| 8   | `summary.docs[].id` 가 유일하다                                                       | 참조가 엉뚱한 문서로 간다            |

<!-- /contract:invariants -->

여기에 더해 응답은 **strict** 로 검증한다. 계약에서 사라진 필드가 하나라도 남아 있으면 실패다 — 파이프라인 버그를 조용히 흘려보내지 않기 위해서다.

삭제된 문서는 피드 참조에서 걷어내고(prune), 한 피드의 참조가 전부 걷히면 그 피드도 사라진다. 걷어낸 개수는 `validate` 가 항상 보고한다 — 갑작스러운 급증은 rename 추적이 깨졌다는 신호다.

## 누가 이걸 소비하나

현재 소비자는 **sas-webfront 의 개발 서버**다. Vite dev 미들웨어가 이 스크립트들을 자식 프로세스로 띄워 stdout JSON 을 파싱한다. 모듈로 `import` 하지 않는다.

프로세스 경계를 계약 경계로 잡은 이유는 미래 때문이다. 실서버는 Rust 로 만들 예정이고, Rust 는 node 모듈을 import 할 수 없다 — CLI 나 HTTP 로만 부를 수 있다. 지금 개발 서버가 CLI 로 소비해두면 그 통합을 미리 연습하는 셈이고, stdout JSON 은 순수 함수의 반환값과 같은 모양이라 나중에 HTTP 로 승격해도 계약이 흔들리지 않는다.

소비자 쪽에서 이 리포는 git submodule 이지만, 의존성 설치는 소비자가 자동으로 하지 않는다(`pnpm install` 을 한 번 직접 돌린다). 미설치 상태로 부르면 자식 프로세스가 시끄럽게 죽고 소비자가 설치 안내를 띄운다 — 조용히 빈 데이터로 통과하지 않는다.

## 개발

```bash
pnpm test              # vitest
pnpm test:coverage
pnpm format            # prettier --write .
pnpm format:check
```

`wiki/` 는 prettier 대상에서 제외한다 — append-only 데이터이고, 포매터가 문서를 손대면 그 커밋이 rename 추적·불변성 게이트를 흔든다. (문서 정체성은 frontmatter UUIDv7 이고, 커밋 해시는 **피드 id 와 히스토리 앵커**로 남는다.)

이 리포는 eslint 를 쓰지 않는다. 제품은 데이터고 스크립트는 그 데이터를 읽는 도구라는 성격 때문이다.
